# ADR-0002: Pickle для сохранений

**Дата:** 2026-05-03 (зафиксировано задним числом)  
**Статус:** Accepted, but with planned migration

## Контекст

Игра должна уметь сохранять и загружать состояние: персонажа, локации, NPC, квесты, текущую позицию игрока.

Состояние — это сложный граф Python-объектов с наследованием от внешнего пакета `dnd_5e_core`.

## Решение

Используем **`pickle`** для сохранений. Файлы — `~/AppData/Local/DnD_LLM_Game/saves/save_{1..10}.pkl` (10 слотов).

## Альтернативы

1. **JSON + ручная сериализация** — много кода для рекурсивного to_dict/from_dict, особенно с наследуемыми классами
2. **JSON + Pydantic** — у нас уже Pydantic, но `Character` наследуется от dataclass'а из внешнего пакета (`dnd_5e_core.Character`), миграция нетривиальна
3. **SQLite** — overkill для одиночной игры; не нужны queries
4. **dataclasses.asdict + JSON** — теряет типизацию, не работает с наследованием от чужих классов

## Последствия

**Плюсы:**
- Работает «из коробки» с любыми Python-объектами
- Никакого ручного маппинга
- Один pickle.dump / pickle.load

**Минусы:**
- ⚠️ **Хрупко к рефакторингу классов** — переименование `Character` → `PlayerCharacter` сломает все старые сейвы
- ⚠️ **Хрупко к изменению модулей** — pickle хранит полный путь класса (`game.core.entities.character.Character`)
- ⚠️ **Никогда не загружать чужой pickle** — может выполнить произвольный код. Не критично для одиночной игры, но важно если пользователи будут делиться сейвами
- Не читаем человеком (нельзя редактировать сейв вручную)
- Версионирование нужно делать руками

## Когда мигрируем

Когда хотя бы одно станет правдой:
- Игроки хотят **делиться сейвами** (security)
- Данные стабилизировались, и мы хотим **читаемые сейвы** для отладки
- Нам нужна **миграция между версиями игры**

Скорее всего — JSON с миграционными скриптами + явная версия в файле.
