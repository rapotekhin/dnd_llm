# ADR-0009: Протокол Godot ↔ LLM-бэкенд

**Дата:** 2026-10-18
**Статус:** Accepted

## Контекст

[ADR-0007](0007-godot-client-python-llm-backend.md) выбрал транспорт: WebSocket + JSON-RPC 2.0, semver-версии, общий токен, `wss://` через прокси, бэкенд без состояния игры, обратные вызовы `engine.*`, транзакцию хода, отсутствие стриминга. [ADR-0008](0008-engine-decides-llm-narrates.md) задал, что ЛЛМ предлагает, а движок решает.

Этот ADR фиксирует сам протокол: подключение, методы, форму сообщений, ошибки, таймауты, логи и тестирование. Источник истины для полей — JSON Schema в `contract/`, выгруженная из Pydantic-моделей ([ADR-0007](0007-godot-client-python-llm-backend.md) §3). Здесь — смысл и правила. Ниже — ответы автора на 24 вопроса.

## Решение

### 1. Подключение

```
Godot                                     llm_server
  │── WS upgrade, Authorization: Bearer <token> ──►│  неверный токен → HTTP 401, сокет не открывается
  │── session.hello {protocol_version, client_version} ──►│
  │◄── {protocol_version, server_version, model, limits} ──│  major не совпал → ошибка version_mismatch, закрытие
  │   ... ходы, саммари, справка ...
  │◄── WS ping каждые 20 с / pong ──────────────────│  нет pong → разрыв
```

- **Токен — в заголовке** при апгрейде WebSocket, а не в URL: не оседает в логах прокси.
- **`session.hello` — первое сообщение.** До него любой другой метод получает ошибку `not_initialized`. Без hello за 10 с соединение закрывается.
- **Живость — WS ping/pong сервера** (uvicorn) раз в 20 с. Заодно прокси не рвёт простаивающее соединение.
- Godot переподключается сам с нарастающей паузой. Статус соединения показывается в меню и HUD.

### 2. Общие правила сообщений

- **JSON-RPC 2.0**, запросы идут в обе стороны по одному сокету.
- **id — строки с префиксом стороны:** `g-17` от Godot, `s-42` от сервера. Коллизий нет, логи читаются.
- **`turn_id`** генерирует Godot (`t-<счётчик>`). Он связывает ход, обратные вызовы и резервы эффектов.
- **Один активный ход на соединение.** Новый `turn.request` во время активного получает ошибку `turn_in_progress`. Саммари, справка и статус могут идти параллельно с ходом. Общий лимит одновременных ходов на сервер задаётся в конфиге (по умолчанию 1).
- **Размер сообщения ≤ 1 МБ.** Превышение закрывает соединение с обеих сторон.
- **Язык — всегда русский.** Поля `locale` нет; EN добавится minor-версией протокола (новое необязательное поле).

### 3. Методы

**Godot → бэкенд**

| Метод | Параметры | Результат |
|---|---|---|
| `session.hello` | `protocol_version`, `client_version` | `protocol_version`, `server_version`, `model`, `limits` (размер сообщения, таймауты, лимиты хода) |
| `session.status` | — | `model`, `server_version`, дневной лимит и потрачено сегодня |
| `turn.request` | `turn_id`, `mode`, `kind`, `input`, `snapshot` | `turn.result` (ниже) |
| `turn.cancel` | `turn_id` | `ok`; активный `turn.request` завершается ошибкой `turn_cancelled` |
| `summary.request` | `kind`, `subject_id`, `previous`, `events` | `summary`, `usage` |

- **`mode`** = `exploration` | `social` | `trade` (позже `combat`). У каждого режима свои промпты и набор инструментов, но общий контракт хода.
- **`kind`** = `enter` (вход в комнату, описание сцены) | `resume` (возврат из диалога/торговли) | `action` (ввод игрока). У `enter` и `resume` поле `input` пустое.
- **`summary.request`**: `kind` = `location` | `dialogue` | `npc_memory`. Godot вызывает его сам при выходе из локации или диалога и кладёт результат в сейв. Входные данные — журнал событий движка, а не пересказ ЛЛМ.

**Бэкенд → Godot** (только внутри активного хода, белый список)

| Метод | Параметры | Результат |
|---|---|---|
| `engine.check` | `turn_id`, `skill` или `save`, `dc_tier`, `target_id?`, `advantage_reason?`, `contest?` {`npc_id`, `skill`} | `check_id`, броски d20, `bonus`, `total`, `dc`, `success`, `nat`, `blocked` (повтор заблокирован — прежний итог) |
| `engine.validate` | `turn_id`, `effect` {`kind`, …} | `accepted` + `effect_id` или `rejected` + `reason` |
| `engine.lookup` | `kind` (`rule` / `spell` / `feature` / `condition` / `item` / `npc`), `id` | данные SRD или NPC текущей сцены |
| `engine.find_items` | `query`, `base?`, `properties?` | похожие предметы каталога (бэкенд добавляет свою библиотеку, [ADR-0008](0008-engine-decides-llm-narrates.md) §6) |

- `engine.lookup` не отдаёт скрытое и другие локации. Это только справка по белому списку.
- Таймаут ответа Godot на `engine.*` — в конфиге бэкенда. Истёк — ход падает с `engine_timeout`.

### 4. Снимок и результат хода

**`snapshot`** — полный, но компактный, собирается Godot на каждый ход:

- **сцена:** локация, комната, выходы с id, NPC сцены (id, имя, роль, отношение), зацепки скрытого (без самого скрытого), время суток;
- **персонаж — итоговыми числами:** класс и уровень, HP, AC, состояния, навыки и спасброски с итоговыми бонусами, заклинания и способности по названиям. Детали модель дозапрашивает через `engine.lookup`;
- **история:** последние ходы, пока влезают в бюджет символов из данных; более старое покрывают саммари;
- **саммари:** локации и памяти NPC сцены;
- **лимиты хода:** проверки, эффекты, бюджет наград ([ADR-0008](0008-engine-decides-llm-narrates.md) §4).

**`turn.result`**:

| Поле | Смысл |
|---|---|
| `turn_id` | ход |
| `narration` | текст мастера (для `social` — реплика NPC) |
| `options` | 1–3 «интересных» варианта. Детерминированные кнопки (выходы, NPC, предметы) Godot строит сам |
| `effect_ids` | какие из зарезервированных эффектов применить |
| `check_ids` | проверки хода (для карточек) |
| `next_mode` | предложение сменить режим: `{mode, npc_id?}`. Godot проверяет, что NPC в сцене |
| `usage` | токены вход/выход, $, модель, остаток дневного лимита |

### 5. Транзакция хода

1. `engine.validate` **резервирует** принятый эффект под `turn_id` и возвращает `effect_id`. Мир пока не меняется.
2. `turn.result` перечисляет `effect_ids`. **Godot применяет только свои резервы** с этими id, одной транзакцией. Подделать эффект в ответе нельзя: полного эффекта в ответе нет.
3. Зарезервированные, но не перечисленные эффекты (модель передумала) отбрасываются.
4. **Ошибка, отмена, таймаут или обрыв** — все резервы хода сгорают, мир не меняется. Godot показывает «нет связи с мастером» и предлагает повторить.
5. **Идемпотентности нет.** Если связь упала после того, как бэкенд досчитал ход, ход теряется, а повтор — это новый ход с новым `turn_id`. Бэкенд остаётся без состояния. Цена — повторно потраченные токены в редком случае.

### 6. Таймауты и повторы

| Что | Значение |
|---|---|
| Ход целиком | 90 с, в конфиге бэкенда; у Godot свой таймер чуть длиннее |
| Ответ Godot на `engine.*` | в конфиге бэкенда |
| `session.hello` после подключения | 10 с |
| WS ping | каждые 20 с |
| Повторы OpenRouter (429, 5xx, невалидный вывод) | бэкенд сам, до 2 раз с экспоненциальной паузой, в пределах таймаута хода |

### 7. Ошибки

Стандартные коды JSON-RPC (−32700 parse error, −32600 invalid request, −32601 method not found, −32602 invalid params, −32603 internal error) плюс доменные в диапазоне −32000…−32099. В `error.data`: `reason` (строка) и `retryable` (bool).

| Код | `reason` | `retryable` | Когда |
|---|---|---|---|
| −32001 | `version_mismatch` | нет | major протокола не совпал |
| −32002 | `not_initialized` | нет | метод до `session.hello` |
| −32010 | `turn_in_progress` | да | второй ход во время активного |
| −32011 | `turn_cancelled` | да | `turn.cancel` |
| −32012 | `turn_timeout` | да | ход дольше лимита |
| −32020 | `llm_unavailable` | да | OpenRouter не ответил после повторов |
| −32021 | `llm_invalid_output` | да | вывод не прошёл схему после повторов |
| −32030 | `budget_exceeded` | нет | исчерпан дневной лимит расходов |
| −32031 | `server_busy` | да | достигнут лимит одновременных ходов сервера |
| −32040 | `engine_timeout` | да | Godot не ответил на `engine.*` |
| −32041 | `engine_error` | нет | ошибка в обработчике `engine.*` |

Неверный токен — HTTP 401 при апгрейде, до JSON-RPC.

### 8. Валидация, логи, тесты

- **Бэкенд** всегда проверяет входящие сообщения Pydantic-моделями.
- **Godot** всегда делает лёгкую проверку при разборе (обязательные поля и типы). В отладке и тестах — полную проверку по JSON Schema из `contract/`.
- **Логи бэкенда:** всегда метаданные (метод, id, `turn_id`, длительность, токены, ошибки). Полные тела сообщений — только на уровне DEBUG. Токен не пишется никогда.
- **Кассеты на двух уровнях:**
  - Godot пишет протокольные сообщения в журнал команд. Это даёт реплей без бэкенда и mock-сервер с кассетами для gdUnit4;
  - бэкенд по флагу записывает ответы OpenRouter. Так pytest гоняет агентов без денег и без сети.
- **Контрактные тесты:** схемы в `contract/` совпадают с моделями (CI). Обе стороны проходят записанные сценарии.

### 9. Уточнения после спайка связи

[Спайк](../connectivity-spike.md) (2026-10-18, v0.3.4) подтвердил транспорт и добавил:

- **`PROTOCOL_VERSION` начинается с `0.1.0`.** Пока major = 0, несовместимо и изменение minor (semver §4), поэтому при рукопожатии сверяются major и minor. С `1.0.0` — только major.
- **Клиентские коды Godot** (по сети не ходят): −32090 `connection_lost` (обрыв, все ждущие вызовы падают), −32091 `client_timeout` (свой таймер клиента), −32092 `message_too_big` (исходящее больше 1 МБ).
- **Таймаут подключения на клиенте — 10 с.** `WebSocketPeer` может висеть в CONNECTING без ошибки.
- **Godot не отличает отсутствие сервера, HTTP 401 и ошибку TLS** — все дают закрытие до открытия. Экран «бэкенд недоступен» называет все три причины.

### 10. Протокол 0.2.0 (v0.4.1)

Первая версия с агентами. Несовместима с 0.1.x: снимок стал типизированным.

- **Снимок** — Pydantic-модель `Snapshot`: `scene` (локация, комната, выходы с id, NPC с полом и отношением −3…+3, зацепки, флаги), `character` (итоговые бонусы навыков и спасбросков, HP, КД, монеты в медяках, снаряжение с id), `history` (по бюджету символов), `summaries` (`location`, `dialogue:<npc_id>`), `limits`.
- **Выбор модели.** `session.hello` и `session.status` отдают `models` — белый список сервера с ценами за миллион токенов. Игрок выбирает модель в настройках, она идёт полем `model` в `turn.request` и `summary.request`. Модель вне списка — `invalid_params`.
- **`turn.request.npc_id`** — собеседник в `social` / `trade`; он должен быть в сцене.
- **Эффекты v0.4.1:** `move`, `damage` (тяжесть и тип; кубики по таблице DMG бросает движок), `heal` (сила лечения), `coins`, `give_item` (по `item_id` или новый `item` из словаря свойств), `take_item`, `npc_attitude`, `flag`. Состояния, квесты, опыт и время — в M2.
- **`engine.validate`** отвечает `accepted`, `effect_id`, `reason`, `summary` (строка для игрока: «−7 HP (огонь)») и `item_id` для нового предмета. Id нового предмета детерминирован по названию, базе и свойствам, поэтому один предмет из библиотеки бэкенда и из сейва совпадает.
- **`engine.lookup`** отвечает `{found, data}`, `engine.find_items` — `{items}` с полем `source` (`catalog` / `session`; бэкенд добавляет `library`).
- **Детерминированные действия без модели:** выход в соседнюю комнату и начало разговора с NPC — кнопки Godot. Движок меняет состояние сам и просит у мастера только описание (`kind=enter`). Конец разговора — `kind=resume`.
- **Повторы OpenRouter** только пока ход не обращался к движку: повтор после броска перебросил бы проверку.

### 11. Протокол 0.2.1 (v0.5.0)

Персонаж 5e. Совместим с 0.2.0 (сравнение по major.minor): новые поля необязательны.

- **`character`** дополнительно несёт `background`, `abilities` (значения Сил…Хар), `proficiency_bonus`, `skill_proficiencies`, `speed`, `equipped` (названия надетого и взятого в руки), у заклинателей — `cantrips`, `spells` (подготовленные и всегда подготовленные, по названию), `spell_slots` (`level`, `left`, `max`), `spell_save_dc`. `class_name` включает подкласс: «Жрец (Домен Жизни)». Умения — названиями, без текста.
- **`engine.lookup`**: новый `kind = feature` (умения классов и черты рас); `spell` и `feature` принимают id SRD или русское название, как в листе. Ответ о заклинании — с полем `known`, об умении — `has`.

### 12. Протокол 0.2.2 (v0.5.1)

Вселенные и настройки мастера. Совместим с 0.2.x: новые поля необязательны.

- **`snapshot.world`** — пакет и настройки игры: `name`, `lore`, `tone`, `magic`, `dm_style` (`classic` / `literary` / `dry` / `ironic`), `violence` (`mild` / `medium` / `graphic`), `lines`, `veils`. Бэкенд кладёт в системный промпт лор, запрет на чужие сеттинги, правила стиля (у сухого — свой лимит длины) и границы контента. Тон пакета заменяет тон по умолчанию.
- **`character.backstory`** — история готового или созданного персонажа.

### 13. Протокол 0.3.0 (v0.5.2)

Новый вид хода, поэтому minor (в 0.x это несовместимо с 0.2).

- **`turn.request.kind = rest`** — игрок отдохнул (движок уже всё восстановил), мастер описывает утро.
- **`engine.check.result.revealed`** — тексты скрытого, которое нашла эта успешная проверка; `blocked: true` — повтор проваленной проверки без изменений, итог прежний, броска не было.
- **`snapshot.scene.found`** — скрытое, которое игрок уже заметил или нашёл в этой комнате (факты для описания).

### 14. Протокол 0.4.0 (v0.5.3)

Новые виды хода — minor.

- **`turn.request.kind = deal`** — игрок заключил сделку панелью, движок её уже провёл; `input` — строки сделки и итог словами («торговец доплачивает игроку …»). **`kind = haggle`** — игрок торговался кнопкой, движок бросил проверку; `input` — итог торга.
- **`snapshot.trade`** (только в режиме trade) — кошелёк торговца, его товары и цены за штуку, что он купит у игрока и за сколько, выигранный процент торга, блок торга на сегодня. Цены считает движок; мастер их только называет.
- **`engine.check.result.note`** — факты движка для мастера; сейчас — итог торга, когда `persuasion` / `deception` с `target_id` торговца в режиме trade трактуется как торг (DC по отношению, а не по ступени).
- В режиме trade движок отклоняет `coins`, `give_item`, `take_item`; `next_mode = social` к тому же собеседнику игнорируется (панель закрывает игрок).

### 15. Протокол 0.5.0 (v0.5.4)

- **`turn.request.kind = quest`** — игрок выполнил задание пакета кнопкой, движок уже отметил его и выдал награду; `input` — что произошло (`done_text` пакета) и награда.
- **`snapshot.quests`** — задания игрока (`id`, `title`, `description`, `done`): мастер может на них ссылаться, но не объявляет выполненными и не даёт за них опыт.
- Опыт — только движок (бой, задания). Эффекта `xp` у мастера нет и не будет (решение автора v0.5.4; заменяет «опыт смешанно» из плана M2).

### 16. Протокол 0.6.0 (v0.6.0)

- **Эффекты** `cast` (`spell`, `slot_level?`), `condition` (`condition` из 12 состояний SRD, `on`, `until` short_rest | long_rest), `use_feature` (`feature`, `amount`), `use_item` (`item_id`). Движок проверяет готовность заклинания и ячейки, остаток использований, наличие предмета — с учётом уже зарезервированного в этом ходе.
- **`turn.request.kind = ability`** — игрок кнопкой сколдовал, использовал умение или предмет, движок уже применил; `input` — факты. **`kind = downed`** — 0 HP вне боя, персонаж очнулся с 1 HP; мастер описывает цену.
- **Снимок:** `character.resources` (имя, осталось, максимум), `hit_dice_left`, `concentration`; `scene.npcs[].trader`.

### 17. Протокол 0.7.0 (v0.6.1)

- **Режим `combat`** и виды хода **`combat_start`** (движок начал бой: кто где, инициатива), **`combat_round`** (строки движка за раунд, в конце — «Итог боя»), **`death`** (гибель героя: последние строки и путь героя — эпитафия). В бою `kind = action` — импровизация игрока, стоит его действия.
- **`snapshot.combat`** — раунд, враги (id, имя, вид SRD, расстояние в футах, сторона, статус, здоровье словом — без чисел), упал ли герой, строки раунда, итог.
- **Эффекты:** `damage` и `condition` с `target_id` врага (импровизация в бою); **`start_combat`** (`enemies` [{`monster`, `count`, `name`}]) — мастер зовёт врагов, движок проверяет бюджет опыта уровня. В бою `move`, `coins`, `give_item`, `take_item`, `npc_attitude`, `start_combat` отклоняются. `next_mode = combat` с `npc_id` — нападение на NPC сцены.

### 20. Протокол 0.10.0 (v0.6.5)

- **`turn.result.option_costs`** — цена каждого варианта в медных (0 — бесплатно); списывает движок при выборе, мастер получает «[движок уже списал …]» в `input`.
- **Эффект `advance_time`** (`minutes` 1–720) — время в сцене; движок держит предел и отклоняет его в бою.
- **Вид хода `wait`** — игрок подождал кнопкой, `input` — строки движка.
- **`CombatFoe.conditions`** — состояния врага словами с оставшимися раундами.
- Кража словами: проверка Ловкости рук с `target_id` NPC — исход и добыча в `note`, эффекты к краже мастер не добавляет.

### 19. Протокол 0.9.0 (v0.6.3)

- **`snapshot.quests[].step`** — текущий шаг задания с шагами; закрывает шаги только движок.
- **`scene.time_of_day`** заполняется: «утро» / «день» / «вечер» / «ночь», в темноте — «, темно».
- **Вид хода `trap`** — игрок обезвредил найденную ловушку (или она сработала), `input` — строки движка. `kind=enter` получает в `input` строки пути (ловушка, время, тайник, шаги заданий), если они были.
- Свойства предметов `saves_plus1` и `stealth_advantage`.

### 18. Протокол 0.8.0 (v0.6.2)

- **`snapshot.combat`:** у врага `surprised` (застигнут врасплох) и статус `truce` (опустил оружие); `player_hidden` (игрок спрятался); `incoming` [{`names`, `side`, `in_rounds`}] — подкрепления на подходе; итог боя `truce`.
- **`scene.sneaking`** — игрок крадётся.
- **`start_combat` в бою** — подкрепление: `side` (`left` / `right`), движок пускает врагов с края поля в следующем раунде, если враги в бою, на подходе и новые укладываются в бюджет опыта уровня.
- **Проверка Запугивания / Убеждения в бою** — переговоры: Сл и исход решает движок (сдача, бегство, перемирие), итог — в `note` результата `engine.check`.

## Альтернативы

- **Токен в URL / только в hello.** Проще, но токен оседает в логах прокси, либо открытый сокет живёт до первого сообщения.
- **Метод на каждый режим** (`exploration.turn`, `social.turn`). Схемы расходятся, а общая логика хода (проверки, эффекты, транзакция) дублируется.
- **Отдельный метод вариантов действий** — второй вызов ЛЛМ на ход, как сейчас.
- **Диф снимка вместо полного** — бэкенд перестаёт быть stateless.
- **Свободное чтение состояния (`engine.get`)** — ломает «скрытое не видно» из ADR-0008.
- **Повторная валидация полного эффекта при применении** — работает, но позволяет бэкенду прислать эффект, которого движок не видел. Резервы надёжнее.
- **Кэш результата хода по `turn_id`** — экономит токены при обрыве, но добавляет состояние в бэкенд и усложняет связь с резервами.

## Последствия

- ✅ Класс багов «ввод во время думает» и «resume не туда» исключён протоколом: один активный ход, явные `kind` и `turn_id`.
- ✅ Ход атомарен: обрыв на любом шаге не оставляет мир в промежуточном состоянии.
- ✅ Один вызов ЛЛМ на ход (наррация + варианты) вместо двух-трёх.
- ✅ Реплеи и тесты обеих сторон работают без сети и без денег.
- ⚠️ Без идемпотентности редкий обрыв после расчёта хода тратит токены дважды.
- ⚠️ Резервы эффектов — новое состояние в Godot: нужны тесты на их сгорание при отмене и обрыве.
- ⚠️ Полный снимок каждый ход тратит токены. Держим его компактным, детали — через `engine.lookup`.
- ⚠️ Лимит 1 МБ и бюджет истории придётся подбирать на реальных сессиях.
