# ADR-0014: сервер мастера запускается вместе с игрой

**Статус:** принято (v0.7.66.1)

## Контекст

По [ADR-0007](0007-godot-client-python-llm-backend.md) игра и бэкенд мастера — два процесса, и сервер поднимал сам игрок: `uv`, `.env`, отдельное окно. Автор хочет один запускаемый файл без ручного подъёма сервера. Ключи из `.env` не должны попасть в билд.

## Решение

`tools/build_game.py` замораживает `llm_server` в `server.exe` и кладёт его рядом с игрой в `build/release/<версия>/`. Игра сама запускает его через `OS.create_process`, если адрес мастера в настройках пуст. Заданный адрес и токен работают как раньше: это внешний сервер, встроенный не запускается.

| Вопрос | Решение |
|---|---|
| Заморозка | PyInstaller, режим папки: `server.exe` и `server_lib/` |
| Адрес | только `127.0.0.1`, порт выбирает система: сервер сам занимает порт `0` и пишет его в файл `master/port`, когда приложение готово (нет гонки между выбором порта и его занятием) |
| Токен | новый при каждом запуске, 32 случайных байта, только в памяти игры; передаётся переменной окружения `LLM_SERVER_TOKEN` |
| Ключ OpenRouter | в `backend.cfg` игрока, `OPENROUTER_API_KEY` окружением дочернего процесса; в билд не входит, `build_game.py` проверяет это поиском значений из `.env` по всем файлам билда |
| Передача окружения | в Godot у `create_process` нет параметра окружения: игра ставит переменные себе, запускает процесс и сразу снимает их |
| Выход | `_exit_tree` автолоада `Backend` вызывает `OS.kill`; на падение самой игры у сервера есть сторож: поток ждёт конца процесса `LLM_SERVER_PARENT_PID` и завершает сервер |
| Падение сервера | игра замечает конец процесса и перезапускает его до 3 раз подряд, новый порт и токен подхватывает новый клиент; потом окно с причиной и журналом `master/server.log` |
| Плохой ключ | код выхода `3`: без перезапусков, окно просит другой ключ. Нет сети — не повод останавливаться: ключ остаётся непроверенным, а упавший ход игра обрабатывает как обычно |
| Данные сервера | `master/` в папке профиля игры: бюджет, библиотека предметов, трассы, журнал |

## Почему PyInstaller и режим папки

Замеры на Windows 10, Python 3.13, заглушка вместо модели, время до файла с портом:

| Вариант | Размер | Старт | Процессов | После `OS.kill` | Сборка |
|---|---|---|---|---|---|
| PyInstaller, папка | 44 МБ | 1,3 с | 1 | ничего | 77 с |
| PyInstaller, один файл | 26 МБ | 1,7 с | 2 | живой дочерний процесс | 50 с |
| Nuitka, один файл | 34 МБ | 2,2–2,8 с | 2 | живой дочерний процесс | 33 мин |

Один файл отпал из-за процессов: загрузчик распаковывает программу и запускает её вторым процессом, и `OS.kill` убивает только загрузчика. Сторож спас бы и этот случай, но штатный выход не должен на него опираться. Nuitka вдобавок компилируется в десятки раз дольше: сборка идёт в конце каждой версии. Папка не мешает игроку: запускается всё равно один `BetweenTheRolls.exe`.

## Отвергнуто

- **`py4godot`, `PyBundleGodot`, `godot-python`**: Python внутри процесса Godot. Падение мастера роняет игру, а бэкенд остаётся обычным сервером со своим протоколом, так что плагин ничего не упрощает.
- **Docker**: требует установки у игрока.
- **Порт, выбранный игрой**: между проверкой и запуском сервера порт могут занять.
- **`OS.execute_with_pipe`** (обмен через stdin и stdout вместо сокета): более закрытый вариант на будущее. Порт вообще не нужен, а значит, к серверу не подключиться и локально, и токен становится лишним. Цена: новый транспорт на обеих сторонах, потому что протокол сейчас живёт на WebSocket ([ADR-0009](0009-godot-backend-protocol.md)), в том числе переподключение и серверные запросы `engine.*`. Пока сервер слушает только `127.0.0.1` с одноразовым токеном, выигрыш этого не стоит.

## Последствия

- Запуск из редактора без `server.exe` идёт на адрес разработчика `ws://127.0.0.1:8765/ws`, как раньше. `BTR_SERVER_EXE` указывает замороженный сервер для такого запуска.
- `backend.cfg` с заполненным адресом остаётся внешним сервером: чтобы перейти на встроенный, поле адреса надо очистить.
- Ключ лежит в `backend.cfg` открытым текстом, в папке пользователя, рядом с токеном. Шифрование без пароля игрока ничего бы не дало: ключ для расшифровки лежал бы рядом.
- Сборка теперь требует `uv` и группу зависимостей `freeze`.
