# ADR-0007: Godot-клиент и Python LLM-бэкенд

**Дата:** 2026-10-18
**Статус:** Accepted. Заменяет [ADR-0004](0004-pygame-prototype.md)

## Контекст

Прототип на Pygame упёрся в ручной UI и фоновые потоки с очередями. Большинство багов из ревью (B1, B2, B9, B11, B19) — это рассинхрон потоков и строковых сообщений между ними. Правила 5e частично считает ЛЛМ (модификаторы, успех броска), и это нарушает [столп 1](../../vision/pillars.md).

В соседнем проекте автора (hive_world_shop) на Godot 4.7 уже отлажены процессы: чистый `core/` без нод, JSON-сейвы с миграциями, gdUnit4, dev-консоль, реплей.

Автор хочет держать ЛЛМ-логику в отдельном Python-бэкенде, чтобы его можно было развернуть на сервере, а всё остальное перенести в Godot. Ниже — ответы автора на 24 вопроса перед стартом.

## Решение

### 1. Кто чем владеет

| Godot (`game/`) — источник истины | Python (`llm_server/`) — ГМ |
|---|---|
| UI, экраны, ввод | Промпты, агенты Pydantic AI, цикл инструментов |
| Состояние мира и сейвы | Сборка контекста из присланного снимка |
| **Все правила 5e:** кубики, проверки, бой, отдых, уровни | Вызов OpenRouter: повторы, таймауты, учёт токенов |
| Валидатор эффектов, бюджет наград | Генерация саммари и памяти NPC |
| **Хранение** саммари, памяти NPC и журнала (часть сейва) | — |

- В бэкенде нет ни одной формулы 5e. Он описывает происходящее и выбирает, но ничего не считает.
- **Бэкенд без состояния игры.** Каждый запрос несёт снимок от Godot: сцена, компактный лист персонажа, последние N ходов, саммари. Перезапуск бэкенда ничего не теряет, сейв целиком в Godot.

### 2. Ход и инструменты

Инструменты ЛЛМ, которым нужен движок, проксируются в Godot по тому же сокету:

```
Godot                               llm_server                       OpenRouter
  │── turn.request(snapshot, input) ──►│
  │                                    │── agent.run ──────────────────►│
  │                                    │◄─ tool: request_check ─────────│
  │◄── engine.check(skill, dc_tier) ───│
  │    бросок на seeded RNG движка     │
  │── {d20, total, success} ──────────►│── tool result ────────────────►│
  │                                    │◄─ tool: propose_effect ────────│
  │◄── engine.validate(effect) ────────│
  │── accepted | rejected(reason) ────►│── tool result ────────────────►│
  │                                    │◄─ output ──────────────────────│
  │◄── turn.result(narration, options, accepted_effects, usage)
  │  применяет эффекты одной транзакцией, пишет журнал
```

- **Проверки делает только движок.** ЛЛМ присылает навык и ступень сложности, движок бросает кубики и показывает игроку карточку броска. Результат «успех/провал» модель получает готовым.
- **Эффекты применяются в конце хода, одной транзакцией.** Во время хода движок их только проверяет и резервирует.
- **Отмена:** `turn.cancel` от Godot отменяет asyncio-задачу агента.
- **Стриминга текста нет.** Ответ приходит целиком в `turn.result`.

### 3. Транспорт и контракт

- **WebSocket + JSON-RPC 2.0** в обе стороны. Godot — клиент (`WebSocketPeer`), бэкенд — сервер.
- **Контракт** — папка `contract/`: JSON Schema всех сообщений и тел инструментов + `PROTOCOL_VERSION`. Источник — Pydantic-модели бэкенда (`model_json_schema()`), выгрузка скриптом, CI сверяет схемы с моделями. Godot проверяет входящие сообщения по схемам в отладочной сборке.
- **Версии — semver.** При рукопожатии сверяется major. Несовпадение даёт понятную ошибку в UI, разница в minor совместима.

### 4. Развёртывание

- **Бэкенд — обычный Python-процесс**: на удалённом сервере (режим по умолчанию) или на машине пользователя. **Запуск вручную** (`uv run llm_server`), Godot только подключается по адресу из настроек или флагу `--backend`.
- **Упаковки в exe в M1 нет.** Когда понадобится раздача на машины игроков, путь — встроенный (embeddable) Python с зависимостями в папке. Отдельное решение — тогда же.
- **Один бэкенд — несколько соединений.** Сейчас ожидается один игрок, но каждое соединение изолировано, ничего общего между ними нет. Лимит одновременных ходов — в конфиге.

### 5. Безопасность

- **Ключ OpenRouter — только на сервере** (env/конфиг бэкенда). Игра его не знает и не передаёт.
- **Общий токен** в конфиге сервера и в настройках игры, передаётся в рукопожатии. Без токена соединение закрывается.
- **TLS через обратный прокси** (Caddy/nginx, Let's Encrypt): бэкенд слушает `127.0.0.1`, наружу — `wss://`. Игра разрешает `ws://` только для `localhost`.
- Лимит размера сообщения; бэкенд вызывает у Godot только методы из белого списка `engine.*`.

### 6. ЛЛМ, наблюдаемость, расходы

- **Провайдер — OpenRouter.** Модель задаётся в конфиге бэкенда. Поддержка vLLM — в [бэклоге](../../production/backlog.md), не в M1.
- **Агенты — Pydantic AI** ([ADR-0003](0003-pydantic-ai-over-langchain.md)). Один агент на ход вместо трёх (describe / actions / resolution).
- **Наблюдаемость:** структурные локальные логи всегда, **Langfuse** — при заданных ключах. Logfire убирается.
- **Расходы:** бэкенд считает токены и деньги и возвращает их в каждом `turn.result` (счётчик в HUD). Дневной лимит на токен в конфиге: при превышении — отказ с понятной ошибкой.

### 7. Обрыв связи

Ход не применяется (транзакция). Игра показывает «нет связи с мастером», переподключается и предлагает повторить ход. Инвентарь, лист персонажа, карта и сохранение работают без бэкенда.

### 8. Репозиторий и стек

- **Монорепо:** `game/` (Godot 4.7, GDScript со статической типизацией, gdUnit4), `llm_server/` (Python 3.13, `uv`, FastAPI + uvicorn, pytest, ruff, pyright), `contract/`, `docs/`, `tools/`.
- Pygame-код уходит в `legacy/` до конца M1 ([roadmap](../../production/roadmap.md)).
- Соглашения Godot — по образцу hive: `core/` без нод, seeded RNG, данные в JSON, текст через `tr()`, команды UI → `GameState` → сигналы `EventBus`.

## Альтернативы

- **Всё в Godot, ЛЛМ через `HTTPRequest`.** Один exe, нет второго процесса. Отвергнуто автором: бэкенд нужен на сервере, и Pydantic AI с промптами остаются в Python.
- **Бэкенд владеет правилами (тонкий клиент).** Можно переиспользовать `dnd-5e-core`, но UI ничего не может посчитать сам, а каждое действие идёт через сеть.
- **Двухфазный ход** (бэкенд отдаёт нужные проверки, Godot бросает, второй запрос). Проще протокол, но 2 вызова ЛЛМ на ход: дороже и медленнее.
- **HTTP + SSE / stdio / gRPC.** HTTP неудобен для обратных вызовов из бэкенда, stdio не работает с удалённым сервером, для gRPC в Godot нет готовой поддержки.
- **Бэкенд со своей БД памяти.** Два источника истины, а сейв Godot перестаёт быть полной игрой.
- **Остаться на Pygame.** Ручной UI и класс багов с потоками остаются.

## Последствия

- ✅ Класс багов «потоки + очереди + строковые сообщения» уходит: Godot ждёт ответ через `await`, бэкенд работает на asyncio, сообщения типизированы схемами.
- ✅ Правила 5e детерминированы и тестируемы в одном месте. Броски видны игроку, ЛЛМ не может их подделать.
- ✅ Бэкенд без изменений переезжает между машиной пользователя и сервером.
- ✅ Ключ OpenRouter не попадает в клиент.
- ⚠️ Два языка и два набора тестов. Компенсируем контрактными тестами по `contract/`.
- ⚠️ Игра не работает без бэкенда, кроме офлайн-экранов. Для игрока нужен развёрнутый сервер или ручной запуск Python.
- ⚠️ Ключ сервера и общий токен: кто знает токен, тратит деньги владельца. Смягчаем дневным лимитом и TLS.
- ⚠️ Без стриминга игрок ждёт ответ целиком (несколько секунд). Если станет проблемой — добавим отдельным решением.
- ⚠️ Раздача игрокам без Python отложена (встроенный Python — отдельное решение).
