# ADR-0004: Pygame для прототипа, Godot — потенциально позже

**Дата:** 2026-05-03 (зафиксировано задним числом)  
**Статус:** Accepted

## Контекст

Нужен UI-фреймворк для одиночной desktop-RPG на Python (или близкого стека, чтобы не переписывать всю backend-логику).

## Решение

Используем **Pygame** для прототипа.

Причины:
- Чистый Python — гомогенный стек с LLM-частью
- Минимальная сложность установки
- Хорошо подходит для **вайбкодинга** (быстрых итераций) с ЛЛМ-ассистентом
- Достаточно для текстового UI с простой графикой

## Альтернативы

1. **Tkinter** — стандарт Python, но устаревший вид и плохо с кастомизацией
2. **PyQt / PySide** — мощно, но сложно и тяжеловесно
3. **Web (Flask/FastAPI + HTML/JS)** — пробовали раньше через Streamlit (`app/`, теперь legacy), не подошло для desktop-RPG
4. **Godot** — мощный игровой движок, GDScript похож на Python, но потребует переписать backend или интегрировать через GDExtension

## Последствия

**Плюсы:**
- Один язык
- Быстрая итерация
- Достаточно для прототипа

**Минусы:**
- Pygame **не игровой движок** — нет встроенной системы сцен, ECS, физики, анимации
- Кастомные UI-компоненты пишутся руками (можно увидеть в `character_creation_screen.py` — 2369 строк)
- Слабая поддержка сложной графики (если позже захотим тайлы / спрайты / анимации)

## Когда мигрировать

Сценарии триггера:
- Если решим добавить тайловую графику и анимации (тогда Godot)
- Если вырастут размеры UI-файлов и поддержка станет невыносимой
- Если найдём Python-обёртку над Godot, которая позволит переиспользовать backend

**Сейчас миграция не планируется.**
