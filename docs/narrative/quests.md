# Квесты

## Источник данных

- Структура квеста — `game/core/data/quest.py` (классы `Quest`, `QuestStatus`, `ObjectiveStatus`)
- Список активных квестов — `MainGameState.quests`
- Квесты, привязанные к локации — `Location.quests_in_location`

## Состояния квеста (`QuestStatus`)

- **Скрытый (hidden)** — игрок ещё не знает о квесте, ЛЛМ может «открыть» его при правильных условиях
- **Открытый (open)** — активен, в журнале
- **Завершённый (completed)** — успешно
- **Проваленный (failed)** — окончательно не выполнен

## Состояния цели (`ObjectiveStatus`)

Каждый квест может иметь несколько целей с собственными статусами.

## Открытые vs скрытые квесты

В системном промпте exploration:

```
Открытые квесты в локации: ...
Скрытые квесты (условия открытия): ...
```

ЛЛМ-ГМ знает о **скрытых квестах**, но не должен их раскрывать игроку, пока не выполнены условия открытия. Это позволяет:
- Готовить квесты заранее (в данных локации)
- Открывать их по триггеру (диалог с NPC, найденный предмет, бросок Внимательности)

## Текущее состояние

В стартовых локациях **нет квестов** (`quests_in_location: []`). Это намеренная заглушка — квесты будут добавляться по мере развития контента.

## Автогенерация (план)

Аналогично NPC и локациям, в будущем — `QuestBuilder` как инструмент для ЛЛМ. Промпты для генерации квестов при добавлении класть в `game/core/prompts/quest_creation_prompts.py`.

## Открытые вопросы
