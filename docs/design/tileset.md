# Тайлсет карты

Как рисуется карта места, какие земли и предметы уже нарисованы, какие генератор использует, но рисует чужой картинкой, и чего нет совсем. Начато в v0.8.4.43.16. Стиль — [art-style.md](art-style.md#карта-v084316), код — [godot-client.md](../tech/godot-client.md) («Земля карты»), понятие — [concepts.md](concepts.md) («Земля карты»).

## Как устроено

**Два слоя.** Клетка карты — символ из `cells` в [`layouts.json`](../../game/data/layouts.json): стена, пол, вода, дерево. Его правила (проходимость, видимость) не меняются. Над ним — **земля**: что под ногами (трава, доски, брусчатка), и **предмет**: что стоит на клетке (дерево, валун, стол, дверь). Землю и предмет выбирают данные `grounds`, а не код:

| Поле `grounds` | Что задаёт |
|---|---|
| `cells` | землю по символу клетки; строка — для любого места, словарь — по ключам места: его вид (`temple`, `dunes`…), виды его семьи, форма (`open`, `building`, `tunnels`) и `*` для прочих, самый точный первым (`LayoutGen.ground_keys`, v0.8.4.43.20). Символа нет — берётся строка `.` |
| `order` | порядок земель снизу вверх: на стыке верхняя ложится поверх нижней |
| `sharp` | земли, которые держат границу клетки (стена, крыша), со скосом и тенью на юг и восток |
| `props` | предмет на клетке по символу и тем же ключам места (`B` в руинах — обломки) |
| `size` | размер предмета в клетках (дерево — 1,7) |
| `patches` | пятна другой земли поверх пола по тем же ключам (берутся строки первого ключа, у которого они есть; пустой список — без пятен): `share` и `cell` — пятна по сиду карты, `near` и `width` — кайма вокруг клеток символа (пляж вокруг воды) |
| `repeat` | сколько клеток покрывает одна текстура (и когда брать чёткий набор: `repeat` × клетка в пикселях > половины 512) |
| `colour` | цвет земли, пока у неё нет текстуры |
| `edges` | пары земель с нарисованным краем: `low` и `high` |
| `edge_layout` | 5×5 углов листа краёв: 1 — верхняя земля; каждое окно 2×2 — один из 16 случаев |
| `edge_band` | ширина полосы рисунка вокруг линии края |

**Двойная сетка (dual grid).** `MapGround` складывает землю, предмет и поворот двери каждой клетки в маленькую текстуру. Шейдер [`map_ground.gdshader`](../../game/ui/components/map_ground.gdshader) решает цвет точки по четырём клеткам, чьи центры стоят вокруг неё. Поэтому земли сходятся не по границе клетки, а неровной линией между центрами, и угловых плиток рисовать не нужно: форму края даёт маска с шумом, текстура у каждой земли одна. Острые земли (стена, крыша) остаются на своей клетке. Предметы соседних клеток могут заходить на эту (крона дерева). В том же проходе — плавный туман невидимого и подсветка под надзором. Сетка клеток видна только в бою.

**Генерация карты под двойную сетку.** Одиночная клетка земли превращается в маленькое пятнышко, поэтому генератор кладёт землю пятнами: строка `scatter` вида с `blob: true` — порог по шуму двух октав (`LayoutGen.blobs`) и чистка одиночек (`_despeckle`). После дорог и домов `_tidy` убирает одиночки ещё раз. Предметы (деревья, валуны) разбрасываются по одному, как раньше. Пруд — с берегом по шуму. Здание на открытой карте — стена по краю и крыша `r` внутри.

**Картинки.** Рисует FLUX 3 Klein через OpenRouter, около $0.009 за кадр:

```bash
python tools/tiles/gen_tiles.py draw                    # все задания tiles.json по 3 варианта (--only id,id; --force перерисовать)
tools/anima/.venv-matte/Scripts/python.exe tools/tiles/gen_tiles.py matte   # предметы вырезает BiRefNet
python tools/tiles/gen_tiles.py sheet                   # build/tiles/sheet_ground.png (земля 2×2 — виден шов), sheet_props.png
python tools/tiles/gen_tiles.py install                 # tools/tiles/picks.json → game/assets/tiles/{ground,props}/<id>.png
```

**Картинки не в git.** `game/assets/tiles/` в `.gitignore`: их рисует и ставит `gen_tiles.py` у себя, а в репозитории лежат промты (`tiles.json`) и выбор (`picks.json`). Без картинок карта рисуется цветами `grounds.colour`; сборка (`build_game.py`) берёт те, что стоят локально.

Промты — [`tools/tiles/tiles.json`](../../tools/tiles/tiles.json): общий стиль земли и предмета плюс предмет кадра. Землю FLUX рисует почти ровной, но не бесшовной: скрипт смешивает кадр с ним же, сдвинутым на половину (`seamless`), — 512 px. Предмет — 256 px с прозрачным фоном. `install` кладёт и чёткий набор для близкого зума (v0.8.4.43.21): землю — тем же `seamless` из сырого кадра FLUX в 1024 px (`ground_hi/`), предмет — вырезанным `matte` в 512 px (`props_hi/`). У листа края своего набора нет: кадр FLUX и есть 1024 px.

**Как добавить землю или предмет.**

1. Строка в `tools/tiles/tiles.json` (`ground` или `props`), `draw` → `sheet`, выбрать вариант в `picks.json`, `install`.
2. Земля: её id в `grounds.order` на своё место по высоте, цвет в `colour`, клетка или форма места в `grounds.cells`. Если край должен быть ровным — id в `sharp`. Предмет: строка в `grounds.props` и размер в `size`.
3. Если новая земля нужна пятнами по виду места — строка `scatter` с `blob: true` и новым символом клетки в `cells` либо `patches` по форме.
4. Тест `test_every_square_has_a_ground_of_the_order_and_every_cell_one_of_its_own` проверит, что у каждого символа есть земля, а у предмета — размер.

Земля без текстуры рисуется своим цветом из `colour`, так что данные можно завести раньше картинки.

**Нарисованный край пары земель** (v0.8.4.43.17). Пара — строка `grounds.edges` и, если нужно, своя фраза стыка в `tiles.json` → `edges` (`water__grass`: «травянистый берег с полосой мокрой земли»). `gen_tiles.py draw --only water__grass` строит маску пары на углах `edge_layout` (нижняя земля синяя, верхняя зелёная) и отдаёт её FLUX как образец (`input_references`): он рисует весь лист 4×4 одним кадром, поэтому свет и тон у плиток общие. Линия маски кладётся в альфу листа. `sheet` показывает лист с сеткой плиток, `install` кладёт его в `assets/tiles/edges/`. В игре от листа берётся только полоса вокруг линии, внутри — обычные текстуры земель: без этого целые плитки травы или воды дают шахматку тона (проба 2026-11-12).

**Вещи карты** (v0.8.4.43.24) — тела `rules.things.bodies`: у каждой размер в клетках `size` [длинная, короткая], что она закрывает (`blocks`: путь, взгляд, выстрел), укрытие, материал и вес. Картинка рисуется строго сверху в пропорциях её клеток (`gen_tiles.py`: кадр FLUX 16:9 для 2×1, 21:9 для 3×1, 3:2 для 3×2), вырезается BiRefNet вместе с отбором по цвету фона (плоскую столешницу резак принимает за фон) и кладётся в квадрат длинной стороны. Поверхности — стол, прилавок, стеллаж, верстак, алтарь, столик — пустые: на них потом встанут вещи.

**Новые вещи карты** (v0.8.4.43.44).

- *Найденная ловушка* — тело `trap` на клетке ловушки (`MapSpots.traps`), два рисунка по клетке: капкан, доска с шипами. Пока не найдена — не видна.
- *Плетень* — клетка `f` (непроходима, видно поверх, горит), картинка `fence` — полоса плетня поперёк клетки; поворот вдоль соседей таких же клеток: вверх-вниз — стоя (`grounds.turn` → `line`, `LayoutGen.prop_turn`). Угол берёт строку.
- *Огород* — кусок `garden` (площадь и ворота): грядки `%` за плетнём; `%` на площади и у ворот — пашня (`grounds.cells`).
- *Кладбище* — кусок `graves` развалин: места `spot:grave` (группа `grave` в `spots`), на них могилы `grave` 2×1 в двух видах.
- *Крепь, ковры, солома* — тела `timber` (места пещеры в шахте), `rug` (украшения дома), `straw` (украшения тюрьмы).
- *Глубокая вода* — клетка `$`: середина пруда, где все восемь соседей — вода (`open.deep`, `LayoutGen._deep` после дорог и мостов); одиночная глубокая клетка возвращается мелкой. Стоит 4 движения, мелкая — 2; земля `deep_water` (на болоте и в пещере — та же стоячая), мост через неё кладётся. Край глубокой с мелкой — смешение по маске: лист FLUX рисовал травой вместо мелкой воды.

**Земля без повтора** (v0.8.4.43.41). На большой поляне одна текстура повторялась каждые `repeat` клеток. Шейдер (`ground`) читает её дважды — как есть и зеркально со сдвигом — и смешивает по шуму шагом `blend.scale` на клетку (граница шириной `edge`), а тон всей земли чуть светлее или темнее пятнами `macro_scale` на `macro` (`grounds.blend`). Новых рисунков не нужно, это работает для любой земли; край пары рисует свой лист, как раньше. Стоячая вода перерисована ровным тоном: у прежней тёмные пятна стояли через три клетки.

**Ещё нарисованные края** (v0.8.4.43.41) — 13 пар листом по маске (`edge_repaint`): яма с полом пещеры, травой, землёй и каменистой землёй (осыпающийся край над чёрной глубиной), пол пещеры у скалы (осыпь у подножия), брусчатка с травой и с землёй (выбитые и утонувшие камни), пляж — вода с песком, стоячая вода с полом пещеры (мокрый каменный бортик), с камышом, грязью, травой и песком. Яму пещеры FLUX сначала рисовал полом с трещинами — помогло «вся синяя область — чёрная бездна».

**Открытые куски без случайных валунов** (v0.8.4.43.41): в круге камней все `B` стали менгирами (`A`), у колодца валунов нет — его рисует своя вещь, ряды валунов рынка стали местами припасов `s` (ящики, бочки и телега площади — `spots.groups.storage.bodies.square`). В чанках зданий одиночных `B` уже нет: они заменены местами `spot:` с v0.8.4.43.26.

**Вещи меток, пол по роли, выходы** (v0.8.4.43.40).

- *Вещь метки.* Метка чанка, у которой есть тело в `rules.map.station_bodies`, стоит своей вещью (`MapSpots`): помост `stage` (3×2, проходим), рыночный прилавок под навесом `stall`, рудная жила `vein`, письменный стол `desk`, жернов `millstone`, менгир `standing_stone` (метка `stone` круга камней), колодец `well` (метка `water`). Значение строки может зависеть от места, как в `grounds`: `water` — колодец в городе и ничего в пещере, где вода — само озеро (`LayoutGen.by_keys`).
- *Пол по роли.* Карта помнит роль каждой комнаты (`map.roles` по `ids`, из `layout.role` комнаты пакета), и `LayoutGen.grounds` читает клетку комнаты ключами `role:<роль>` впереди ключей места. Погреб и кухня — каменные плиты `flagstone`, хоть дом из досок. Карта старой сборки без `roles` — пол места везде.
- *Выходы.* Клетка выхода рисуется вещью по его виду (`grounds.exits`, `LayoutGen.props_laid` с выходами карты): у края открытой карты — указатель `signpost` (верх картинки смотрит наружу), на лестницу — `stairs_up` или `stairs_down` (выход помнит `up`, если этаж цели выше), верх к стене рядом. Дверь рисует своя `+`. Поле карты обводит клетку выхода рамкой, а не заливает золотом.

**Варианты и группы** (v0.8.4.43.37). Вещь из `grounds.variants` нарисована в нескольких вариантах: `<id>.png`, `<id>_v1.png`… (`picks.json` — список номеров, `install` кладёт их по порядку, `tiles.json` — список предметов кадра, по одному на вариант). Клетка берёт вариант по `LayoutGen.cell_hash(x, y, сид)` — соседи совпадают в трети случаев, а не всегда. Природная вещь (`grounds.natural.of`) в шейдере чуть меньше или больше (`scale`) и чуть сдвинута (`shift`) по хешу клетки, а под ней мягкая круглая тень (`shade`). Тени всех вещей рисуются первым проходом, потом вещи — так тень соседа не ложится поверх кроны, а две тени сливаются в одну, а не темнеют вдвое. Две или четыре одинаковых вещи рядом `LayoutGen.props_laid` заменяет одной картинкой группы (`grounds.groups`: больше — раньше, пара лёжа и стоя, стоя — с поворотом), остальные клетки группы пусты; проходимость не меняется — её решает символ. В игре так видно, как в играх с тайлами решают «два валуна рядом»: не две одинаковые копии впритык, а одна нарисованная гряда.

**Места вещей на чанках** (v0.8.4.43.26). Метка чанка `spot:<группа>` — клетка, где может стоять вещь группы. Группы и связи лежат в `layouts.json` → `spots`:

| Группа | Буква в чанках | Что встаёт (вес) | Доля |
|---|---|---|---|
| `table` | `t` | стол | 0.9 |
| `seat` | `b` | скамья 3, табурет 1 | 0.9 |
| `storage` | `s` | бочка, ящик, сундук, стеллаж, шкаф — свои веса у кузницы, лавки, храма, конторы, мельницы | 0.6 |
| `decor` | `d` | горшок с растением, статуя (в храме статуя чаще) | 0.5 |
| `pillar` | `p` | колонна | 1.0 |
| `cave` | `c` | кости, грибы, валун; в шахте ящики и бочки | 0.6 |

Движок по сиду игры и комнаты заполняет долю `fill` мест группы телом по весам вида места. Вокруг каждой вещи он ставит её спутников `near`: у стола — две скамьи вдоль него (`same_turn`) и табурет, у кровати — столик, сундук и горшок, у очага — бочка и табурет, у алтаря — два горшка, у костра — пни, у верстака — ящик и табурет, у горна и прилавка — бочка или ящик. Спутник встаёт на клетку рядом с вещью; если места нет, его просто нет. Станция метки и прилавок `C` встают своими вещами: прилавок закрывает всю полосу своих меток вещами по три клетки. Свободные места остаются мастеру: его мебель с `body` встаёт на место своей группы.

| Клеток | Вещи |
|---|---|
| 1×1 | табурет, бочка, сундук, ящик, прикроватный столик, горшок с растением, наковальня, костёр, колонна, статуя, дерево, куст, пень, грибы, кости, занавесь (без рисунка) |
| 2×1 | стол, скамья, шкаф, стеллаж, кровать, очаг, верстак, алтарь |
| 3×1 | прилавок |
| 2×2 | горн, колодец, валун |
| 3×2 | телега |

Где стоит вещь, решает `MapSpots`: вещь комнаты с телом (своим `body` или по виду контейнера) — у своей клетки, станция метки (`rules.map.station_bodies`: горн, наковальня, верстак, очаг, алтарь, кровать, костёр) — на клетках вокруг метки; поворот — по сиду, из четырёх; вещь, закрывающая путь, не перерезает проходы комнаты. Её клетки (`MapSpots.walls`) закрывают ходьбу (`WalkRules.passable`) и взгляд (`SightRules.veiled`), в бою становятся препятствиями с флагами по телу (`FightField._block`: путь — сплошная, взгляд или выстрел — полное укрытие, низкая — половинное); вещь в несколько клеток не толкают. Рисует шейдер земли: картинка вещи хранится на её левой верхней клетке с поворотом (`MapGround.place`, `prop_dims`).

Кодом поверх земли: окно (стекло поперёк стены) и опасная клетка `^` (красная пометка). **Поверхности (v0.8.4.43.29)** — второй слой той же двойной сетки. Огонь, масло, лужа, грязная вода, лёд и кислота — бесшовные текстуры FLUX среди земель (`ground/fire.png`, `oil`, `puddle`, `foul_puddle`, `acid`; лёд — та же земля `ice`). Они ложатся поверх земли с мягким краем между центрами клеток, и одна клетка выходит круглым пятном. Какая поверхность у зоны боя, решают данные: `ground` у вида в `surfaces.kinds` из [`anims.json`](../../game/data/anims.json), а у лужи — по её жидкости (`surfaces.layer.liquids`). Как поверхность движется, задаёт `surfaces.layer.grounds`: `flow` — дрейф картинки, `waver` — рябь, `glow` — мерцание огня. Облака, свет, тьма и паутина остаются рисунками поверх (`SurfaceArt`).

**Лава** (v0.8.4.43.32) — клетка `&` (`lava`: непроходима, видно поверх), земля `magma` (`ground/magma.png`) и листы краёв `magma__cave`, `magma__stony`, `magma__grass` — корка застывшего базальта со светящимися трещинами. Листы нарисованы стилем `edge_repaint`: цвета маски не сохраняются. Лава течёт и светится в шейдере: `grounds.motion` (`flow` — дрейф, `waver` — рябь, `glow` — мерцание), светящаяся земля видна и в темноте. Где лежит: озеро на открытой карте места с тегом `lava` (`open.ponds`: тег → клетка пруда, как вода), залы `cave_lava_lake` и `cave_lava_flow` для комнаты пещеры с этим тегом. Где сходятся три земли (лава, пол и дорога), лист не берётся — там край по маске, ступеньками.

**Мосты** (v0.8.4.43.36) — клетка `_` над водой и `;` над лавой, проходима. Дорога, проложенная по жидкости, кладёт мост (`open.bridges`: жидкость → клетка моста), `LayoutGen._abutments` продлевает его на клетку на каждый берег — иначе на двойной сетке две клетки настила дают пятнышко меньше клетки. Брод куска `tile_path_ford` — тоже мост. Мост — **земля** `planks`, а не вещь: край настила с водой — лист `water__planks` (бревенчатая балка на сваях, тень на воде), пролёт любой длины и с изгибом рисуется сплошь. Вырезанный пролёт поверх воды выглядел наклеенным: свой свет, швы между пролётами.

**Водопады** (v0.8.4.43.36) — `|` и `!` (лава): клетки обрыва, непроходимы, видно поверх, земля под ними — их жидкость. `_falls` после кусков и прудов делает обрыв с одной жидкостью сверху и снизу (или слева и справа) водопадом (`open.falls`); куски `tile_stream_falls_a` / `_b` ведут ручей через обрыв плато. Вид — **полоса пены** у кромки обрыва: гладкий перелив сверху и белая пена ниже, без своей скалы и травы — обрыв рисует карта. Рисует `gen_tiles.py` строкой `strips` в `tiles.json`: маска — полоса на сером внизу клетки обрыва (там карта рисует кромку), по кадру на ширину `<id>@1`, `@2`, `@3` (FLUX держит одну вещь посередине кадра, а не несколько на местах маски), серый вырезается, клетки режутся плитками `grounds.strips.parts` (`_one` из @1, `_left` и `_right` из @2, `_mid` из @3). Клетка берёт плитку по таким же клеткам слева и справа от струи (`LayoutGen.prop_at`), мост над струёй считается струёй; поворот вниз по склону (`grounds.turn` → `fall`), вода в пене течёт в шейдере (`grounds.shimmer`). Не вышло: картинка водопада в каменной рамке («колодец»), кусок пейзажа со своим обрывом в три четверти (наклейка, а повёрнутый — коробка на боку), лента воды во всю клетку (панель поперёк ручья).

## Чего нет ни в генерации, ни в рисунке

- **Кусты** как непроходимое препятствие ниже дерева.

**Открытые места из кусков** (v0.8.4.43.27). Дикое место — лес, поле, холмы, скалы, болото, берег, снега, пустыня, лагерь, «дикое» — собирается из кусков 12×12 (`chunks` с `tile`). Темы кусков:

| Тема | Куски |
|---|---|
| поляна | открытая трава с парой кустов и деревьев |
| роща | купы деревьев, внутри иногда подлесок |
| скалы | выходы камня с осыпью |
| пруд | вода с берегом |
| возвышенность | плато `:` (светлая трава `high_grass`) с обрывом `/` (`cliff`) по краю; где плато сходит на землю без обрыва — пологий подъём; проход между двумя плато, как засада у дороги |
| ручей | прямой, поворот, развилка, исток |
| тропа | прямая, поворот, конец, брод через ручей |

Веса тем — строка `tiles` вида места (у холмов больше плато, у леса — рощ). Ручей и тропа выходят на край куска только двумя средними клетками, поэтому куски стыкуются: вода к воде, тропа к тропе. Генератор кладёт их рядами по сиду, повёрнутыми и отражёнными, подбирая каждый к соседям слева и сверху. Карта 40×40 — это куски 4×4, срезанные по краям. После кусков идёт прежний разброс по шуму, но только по траве и вполовину (`open.tile_scatter`). Обрыв не пройти, но через него видно; плато — обычный пол. Сам обрыв нарисован FLUX листом краёв двойной сетки. Клетки обрыва `/` рисуются травой плато (земля `cliff_top` — та же текстура, `grounds.same`) и остаются невидимой преградой. На стыке `cliff_top` с травой и высокой травой лист краёв (`grass__cliff_top`, `tall_grass__cliff_top`) рисует каменную стенку и тень у подножия. Где плато само сходит на траву, лист не берётся — подъём пологий. Лист обрыва рисуется своим стилем `edge_land`: цвета маски не сохраняются, синее — низина с травой. У него пологая линия в альфе (`gain` 1 вместо 2) и широкая лента (`band` 0.42), чтобы стенка и тень попали в картинку целиком.

Картинка вещи режется по её клеткам (`gen_tiles.py` → `fit`): если FLUX нарисовал вещь поперёк её клеток (кровать стоя при клетках 2×1), вырезка сначала поворачивается на четверть, а не сплющивается (v0.8.4.43.31).
