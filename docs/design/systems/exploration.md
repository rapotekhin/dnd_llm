# Exploration

Основной режим игры. Игрок исследует комнаты, общается с миром, реагирует на события.

## Что видит игрок

1. **Описание сцены** — ЛЛМ описывает текущую комнату (атмосфера, NPC, видимые объекты)
2. **2-4 варианта действий** — сгенерированные ЛЛМ опции
3. **Свободный ввод** — игрок может ввести своё действие, не только выбрать из вариантов

После действия:
- ЛЛМ может задать **уточняющий вопрос** (например: «Куда конкретно ты смотришь?»)
- ЛЛМ описывает **исход** действия (с броском или без)
- Игрок снова получает варианты или переходит в другой режим

## Что происходит технически

В фоновом потоке работают **три Pydantic AI агента** (см. [tech/llm-integration.md](../../tech/llm-integration.md)):

| Агент | Когда вызывается | Output schema |
|---|---|---|
| `describe_agent` | Один раз на вход в локацию | `SceneDescription` |
| `generate_actions_agent` | Перед каждым выбором игрока | `ActionList` (2-4 опции) |
| `resolution_agent` | После каждого выбора игрока | `AgentResolutionOutput` |

**Resolution agent** — главный. Он решает:
- задать вопрос игроку или сразу разрешить действие
- какие инструменты вызвать (`roll_dice`, `rule_db_lookup`)
- какой режим следующий: остаёмся в exploration / переходим в social / trade / combat / меняем комнату

## Контекст системного промпта

ГМ-агент получает в системном промпте:
- Полное описание персонажа (характеристики, способности, заклинания, состояния)
- Текущая локация (название, тип, описание)
- Текущая комната (название, описание)
- **Связанные комнаты** — куда можно перейти (с ID, чтобы ЛЛМ корректно заполнил metadata перехода)
- **NPC в комнате** — с ID
- Сокровища в комнате
- **Открытые и скрытые квесты** локации
- **`location_history_summary`** — краткая запись прошлых посещений (предотвращает разрастание контекста)

См. `game/core/prompts/exploration_prompts.py` для актуального промпта.

## Как ГМ принимает решения о бросках

В системном промпте есть правила:
- Игрок **ищет** → `roll_dice("1d20+WIS_mod", DC=...)` (Внимательность)
- Игрок **убеждает** → `roll_dice("1d20+CHA_mod", DC=...)` (Харизма)
- Игрок делает **опасное** → проверка или спасбросок

ЛЛМ обязан передавать `expression` в нотации кубиков (`"1d20+3"`), а не названием проверки. Это явно прописано в промпте, потому что ЛЛМ путаются.

## Переходы между режимами

Когда `resolution_agent` решает «дальше social/trade/combat/смена комнаты», он возвращает в Pydantic-выводе:

```python
AgentResolutionOutput(
    narration="Ты подходишь к бармену.",
    action="social",
    metadata=ActionMetadata(npc_id="a1f3...")
)
```

Поток exploration:
- Для **social/trade** — **ставит себя на паузу** (не убивается), отправляет UI команду перехода. Когда игрок возвращается из social/trade — поток просыпается, пересобирает агентов с обновлённым `location_history_summary` и продолжает
- Для **combat / смены комнаты** — пишет саммари локации в state и завершается. UI создаёт новый поток после возврата

## Что НЕ умеет (роадмап)

- Создавать новых NPC «на ходу» (нужен инструмент `create_npc`)
- Создавать новые локации/комнаты при выходе за известный мир (нужен `LocationBuilder` как tool)
- Сохранять долгосрочное «знание мира» — сейчас только `location_history_summary` на уровне локации
