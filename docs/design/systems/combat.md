# Combat (планируется)

> ⚠️ **Не реализовано.** `game/core/gameplay/combat.py` пуст.  
> Этот документ — намерения, не описание готовой системы.

## Видение

Пошаговый бой по правилам D&D 5e, в духе **Baldur's Gate 3 / Solasta**:

- Initiative roll → ход за ходом
- Каждый ход: action + bonus action + movement + reaction (potential)
- Полный набор: атаки, заклинания, dash, dodge, help, hide, ready, search

## Что НЕ хотим

- Нарративный бой а-ля «опиши, как ты атакуешь» — это размывает границу со столпом 1 (ЛЛМ ≠ движок)
- Real-time / pause-based — слишком сложно и убивает «настольное» ощущение

## Архитектурное намерение

Те же принципы, что в exploration:

1. **Движок управляет состоянием** — initiative tracker, HP, conditions, slots — всё в Python
2. **ЛЛМ описывает и тактически решает за NPC/мобов** — но через инструменты:
   - `combat_attack(attacker_id, target_id, weapon_id)`
   - `combat_cast_spell(caster_id, spell_id, targets, ...)`
   - `combat_move(actor_id, destination)`
   - `combat_end_turn()`
3. **Игрок выбирает действие через UI** — не через свободный ввод. Это **исключение из столпа 3** (свобода) ради скорости и точности боя
4. **Броски — через `roll_dice`** — все атаки, спасброски, урон

## Открытые вопросы

- **Сетка или абстрактная позиция?** D&D 5e обычно с сеткой 5ft. Нужна ли визуализация позиций или достаточно «ближний/средний/дальний»?
- **AOE заклинания** — без сетки реализовать сложно
- **Multiclassing** — учитываем сразу или после v1?
- **Death saves и стабилизация** — обязательно
- **Скорость хода** — D&D ход может быть долгим. Как не утомить одиночного игрока?
