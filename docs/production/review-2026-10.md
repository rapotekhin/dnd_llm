# Ревью проекта и roadmap переезда на Godot (октябрь 2026)

**Статус:** согласовано автором. Roadmap — в [roadmap.md](roadmap.md), решения переносятся в ADR (M0).
**Основа:** код `main` @ `7b4598b`, документация `docs/`, эталон процессов — `C:\Code\hive_world_shop` (Godot 4.7, ADR-0001…0046).

---

## 0. Главное в пяти пунктах

1. **Игра сейчас — чат с листом персонажа.** У ЛЛМ нет ни одного инструмента, меняющего мир: HP, XP, монеты, предметы, квесты и состояния меняются только руками в инвентаре/торговле. Столп 1 («мир меняется через Python-функции») выполнен наполовину: ЛЛМ мир не портит, но и движок его не меняет. Нет ставок, награды и провала.
2. **Ломается базовый поток.** Возврат из Инвентаря/Карты/Журнала/Персонажа на главный экран убивает поток исследования (`KeyError: 'text'`, подтверждено тестом). Изменение размера окна и настройки молча теряют сессию. Переход в `combat` — тупик.
3. **5e соблюдается в листе персонажа, но не в игре.** Проверки без бонуса мастерства, ЛЛМ сам считает модификаторы, броски скрыты от игрока, нет отдыха и трат ячеек, HP на уровне — максимум кости, у нового персонажа отладочные 5000 XP.
4. **Переезд на Godot оправдан,** но не как порт 1:1. **Решение автора:** игра (UI, состояние, правила 5e) — в Godot, ЛЛМ-логика — отдельный Python-бэкенд (OpenRouter, позже vLLM). Большинство найденных багов — из класса «потоки + очереди + строковые контракты». Он исчезает, если граница — один типизированный протокол: Godot ждёт ответ через `await`, бэкенд на asyncio без потоков. Ядро правил пишем по образцу hive: чистый `core/`, seeded RNG, JSON-сейвы с миграциями, gdUnit4.
5. **Предлагаемый порядок:** M0 решения → **M1 переезд:** фикс багов pygame (v0.3.1) → каркас Godot (v0.4.0) → Python-бэкенд (v0.4.1) → тесты обеих сторон (v0.4.2) → перенос функционала до паритета (v0.5.x) → **M2+:** эффекты, меняющие мир → бой → рогалик-цикл → генерация мира.

## 4. Геймдизайн

### 4.1. Ядро петли

- **Нет ставок и наград.** XP не начисляется (кроме отладочных 5000), HP не меняется, квесты не открываются, монеты движутся только в торговле. Через 15 минут игрок понимает, что любые слова ни на что не влияют. Это убивает и столп 3: свобода без последствий не ощущается свободой.
- **Синдром чистого листа.** «Бесконечная песочница без главного квеста» плюс пустая таверна — игроку нечего хотеть. Нужен генератор мотивации: доска заказов, слухи с ценой, фракции с отношением. В hive это решено кампанией из улик, дедлайнов и мыслей торговца — те же паттерны подходят как «зацепки» сцены.
- **Нет ресурса, который тратится.** 5e держится на дне приключений: ячейки, кости хитов, короткий/длинный отдых. Без истощения классы не отличаются друг от друга в игре, только на листе.
- **Нет провала.** Смерть заявлена как столп жанра (roguelike), но умереть невозможно.

### 4.2. Неточности 5e

| Где | Как сейчас | Как по 5e |
|---|---|---|
| Поиск ([exploration_prompts.py](../../game/core/prompts/exploration_prompts.py), правило 4) | `1d20 + мод. WIS` | Внимательность (WIS) или Анализ (INT) + бонус мастерства, если есть владение; компетентность ×2. Пассивная Внимательность для скрытого |
| Социальные проверки (правило 5) | `1d20 + мод. CHA` | Убеждение / Обман / Запугивание / Выступление + мастерство. Отношение NPC (дружелюбный / безразличный / враждебный) задаёт DC |
| Спасброски (правило 6) | модификатор характеристики | + мастерство в спасбросках класса |
| DC | любое число на усмотрение ЛЛМ | Лестница сложностей 5/10/15/20/25/30. ЛЛМ выбирает ступень, число — движок |
| Повторные попытки | ничто не мешает бросать снова | Повтор — только при изменении ситуации или «взять 10/20»-аналог: время вместо броска |
| HP на уровне | максимум кости (B6) | среднее или бросок |
| Продажа | полная цена (B13) | половина цены. Торг — проверка Убеждения с потолком |
| Отдых | кнопка «Отдых» нарисована, но не работает | короткий (кости хитов) / длинный (HP, ячейки, половина костей) |
| Ячейки заклинаний | не тратятся; у подготавливающих классов могут застрять (B7) | трата и восстановление |
| Броски | скрыты, результат знает только ЛЛМ | Игрок видит карточку броска: «Внимательность DC 15: 12 + 3 = 15 ✓» |
| Обращение | всегда мужской род, пол персонажа в промпт не передаётся (`repr` без пола, [character.py:73](../../game/core/entities/character.py#L73)) | род по полю персонажа |
| Язык данных | названия заклинаний и предметов SRD на английском посреди RU-интерфейса | словарь RU-названий SRD как данные |

### 4.3. Режимы

- **Exploration.** 2–4 варианта от ЛЛМ часто однотипны («Осмотреться», «Поговорить с барменом»). Детерминированные действия — выходы, NPC в комнате, предметы — дешевле и понятнее как кнопки. ЛЛМ нужен для свободного ввода и для 1–2 «интересных» вариантов.
- **Social.** Нет памяти NPC и отношения. Разговор не может ничего изменить: дать предмет, скидку, квест, информацию-флаг. Это главный недоиспользованный ресурс ЛЛМ-игры.
- **Trade.** Механически сделано хорошо (бартер, перетаскивание), но без кошельков, спреда и торга это банкомат (B4, B13). У NPC нет ни лимита денег, ни пополнения ассортимента.
- **Combat.** Для ЛЛМ-игры рекомендую «театр разума» по зонам (вплотную / рядом / далеко / вне досягаемости) вместо сетки: дешевле, отлично ложится на текст, AoE — по зонам. Враги — шаблоны монстров SRD. ЛЛМ выбирает действие врага из списка легальных действий, который даёт движок. Бой — исключение из свободного ввода, и это нормально (уже записано в [combat.md](../design/systems/combat.md)).
- **Создание персонажа.** Мастер на 9 шагов перед первой репликой ГМ при перманентной смерти — высокий порог входа. Нужны готовые персонажи (по одному на класс) и «быстрый старт».

## 5. Архитектура: Godot + Python LLM-бэкенд

**Решение автора:** вся игра в Godot, ЛЛМ-логика в отдельном Python-бэкенде. Бэкенд ходит в OpenRouter, позже в vLLM.

### Кто чем владеет

| Godot (`game/`) — источник истины | Python (`llm_server/`) — «мозг ГМ» |
|---|---|
| UI, экраны, ввод | Промпты, агенты Pydantic AI, цикл инструментов |
| Состояние мира, сейвы (JSON + миграции) | Сборка контекста из присланного снимка, окно истории |
| Правила 5e: кубики, проверки, бой, отдых, уровни | Выбор модели и провайдера, повторы, таймауты, стриминг |
| Валидатор эффектов и бюджет наград | Подсчёт токенов и денег, ответ клиенту |
| Саммари, память NPC и журнал **хранятся** здесь (это часть сейва) | Саммари и память NPC **генерируются** здесь, а хранятся в Godot |

Бэкенд **без состояния игры.** В каждом запросе приходит снимок (сцена, компактный лист персонажа, последние N ходов, саммари), в ответе — текст и предложения. Если бэкенд перезапустить, ничего не теряется: сейв целиком в Godot. Тот же бэкенд потом встаёт на удалённый сервер рядом с vLLM без смены протокола.

### Ход: инструменты ЛЛМ проксируются в движок

```
Godot                         llm_server                      LLM
  │ turn.request(snapshot, input) ─►│
  │                                 │── agent.run ─────────────►│
  │                                 │◄─ tool: request_check ────│
  │◄── engine.check(skill, dc_tier) │
  │  бросок на seeded RNG движка    │
  │── {d20, total, success} ───────►│── tool result ───────────►│
  │                                 │◄─ tool: propose_effect ───│
  │◄── engine.validate(effect)      │
  │── accepted / rejected(reason) ─►│── tool result ───────────►│
  │◄── turn.stream(narration…)      │◄─ output ─────────────────│
  │◄── turn.result(narration, options, accepted_effects, usage)
  │ применяет эффекты одной транзакцией, пишет журнал, сейв
```

- **Транспорт:** WebSocket, двусторонний JSON-RPC 2.0. Godot — клиент (`WebSocketPeer`), бэкенд — сервер (FastAPI/Starlette или `websockets`). Обратные вызовы `engine.*` бэкенд шлёт по тому же сокету и ждёт ответ: функция инструмента в Pydantic AI — `async`, она просто ждёт RPC.
- **Эффекты применяются в конце хода.** Во время хода движок только проверяет их и резервирует. Если ход отменён (сеть, Esc, ошибка), мир не меняется наполовину.
- **Проверки только у движка.** ЛЛМ присылает навык и ступень сложности, движок кидает кубики и показывает карточку броска. Решение «успех/провал» ЛЛМ получает готовым.
- **Отмена:** `turn.cancel` от Godot → `asyncio` отменяет задачу агента. Зомби-ходов, как в B20, нет.

### Контракт

- Папка `contract/` в корне репо: JSON Schema всех сообщений и тел инструментов + `PROTOCOL_VERSION`. Источник — Pydantic-модели бэкенда (`model_json_schema()`), выгрузка скриптом и проверка в CI.
- Godot проверяет входящие сообщения по схеме в отладке и сверяет версию протокола при рукопожатии.
- Контрактные тесты: бэкенд гоняется против записанного «фейкового Godot», Godot — против mock-бэкенда (скрипт-сервер с кассетами).

### Запуск и упаковка

| Режим | Как |
|---|---|
| Разработка | бэкенд запускается отдельно (`uv run llm_server --port 8765`), Godot подключается по `--backend ws://127.0.0.1:8765` |
| Сборка для игрока | бэкенд собран в один exe (PyInstaller/Nuitka) рядом с игрой. Godot стартует его через `OS.create_process` со случайным портом и одноразовым токеном, ждёт `ready`, убивает при выходе |
| Удалённо (vLLM) | тот же протокол по `wss://` с токеном. Godot ничего не знает про модель |

- **Провайдеры:** OpenRouter и vLLM оба OpenAI-совместимые. Один `OpenAIChatModel` с `base_url`, провайдер и модель задаются в конфиге бэкенда. Для vLLM structured output — через guided decoding (JSON Schema).
- **Ключ OpenRouter хранится только в бэкенде** (каталог пользователя, не корень репо). Godot передаёт ключ один раз из экрана настроек и больше его не видит.
- **Безопасность:** бинд только на `127.0.0.1`, токен в рукопожатии, лимит размера сообщений, белый список методов `engine.*`.

### Риски

| Риск | Смягчение |
|---|---|
| Упаковка Python (размер ~60–150 МБ, антивирусы на PyInstaller) | Nuitka или подпись. Сразу в M0 проверить сборку «hello world»-бэкенда и запуск из Godot-экспорта |
| Два языка, правила разъедутся | Правила только в Godot. В бэкенде нет ни одной формулы 5e, только описание и выбор |
| Задержка лишнего хопа и RPC-обратных вызовов | Локально это миллисекунды на фоне секунд ЛЛМ. Ограничить ход: ≤ 3 проверки и ≤ 5 эффектов |
| Рассинхрон версий клиента и бэкенда | `PROTOCOL_VERSION` в рукопожатии, понятная ошибка в UI |
