# Редакторы данных

Две страницы для автора: смотреть, искать, править и создавать данные игры, не открывая JSON руками. Без сборки и без сервера.

| Страница | Что правит |
|---|---|
| `assets.html` | каталог вещей и свойства (`game/data/items.json`), заклинания, классы, подклассы и умения, расы, подрасы и черты, предыстории, языки, монстры (`game/data/srd/*.json`), состояния, эффекты заклинаний, расходники, инструменты и любой раздел `rules.json` и `game.json`; источники сборки `tools/srd/ru.json`, `tools/srd/backgrounds.json`, `tools/srd/promoted.json` |
| `world.html` | пакеты миров `game/data/worlds/<id>/`: `pack.json`, стартовая комната, локации, комнаты (выходы, NPC, встречи с `enemies` / `allies` / `waves` / `help`, открытые края, тайны, закрытые выходы, варианты по флагам), NPC, задания, предметы и услуги пакета, готовые персонажи (`characters.json`) |

## Как открыть

1. Открыть `tools/editors/assets.html` или `world.html` в **Chrome или Edge** (двойной щелчок по файлу).
2. **Открыть папку** → корень репозитория. Можно и `game/data` (без источников сборки `tools/srd`) или папку одного пакета (без подсказок из SRD). Браузер спросит разрешение на запись; в следующий раз хватит кнопки «Открыть снова».
3. Править, **Сохранить** (или Ctrl+S). «Изменения» показывает diff каждого файла до записи.

Другие браузеры:

- **Открыть только для чтения** — выбрать папку `game/data` (или корень); правки скачиваются файлами, их надо положить на место.
- `python tools/editors/serve.py` — страницы на `http://127.0.0.1:8790/tools/editors/` сами открывают данные репозитория и сохраняют на месте (пишет только `.json` в `game/data` и `tools/srd`, слушает только localhost).

## Что умеют

- Список с поиском по всему тексту записи и фильтрами по свойствам этого вида данных: они строятся из самих данных (круг, школа, класс и концентрация заклинания; тип, редкость, свойства и цена вещи; тип, размер и ПО монстра; локация, встреча и тайны комнаты; торговец и комната NPC…). Сортировка по названию, id и числовым полям.
- Форма записи по её полям: строки, числа, да/нет, списки (добавить, убрать, переставить), вложенные объекты; «+ поле» предлагает поля, которые есть у других записей. Вкладка JSON — правка записи целиком.
- Ссылки: поле со ссылкой (выход комнаты, NPC, монстр встречи, вещь добычи, заказчик задания, класс заклинания…) подсказывает id и ведёт к записи. Блок «Связи» — на что ссылается запись и что ссылается на неё.
- «Создать» (поля, общие для большинства записей), «Копия», «Переименовать id» (ссылки на старый id не меняются — «Связи» и проверка покажут их), «Удалить», «Отменить правки».
- Сохранение не трогает остальное в файле: табы, порядок ключей, переводы строк (CRLF / LF) и ручную разметку (`rules.json`, `pack.json`, `characters.json` держат короткие объекты в одной строке — так и остаётся). Новые ключи встают в конец объекта; в отсортированных файлах (`ru.json`, `promoted.json`, каталог вещей) — по алфавиту.

## Собираемые файлы

`game/data/srd/*.json` и каталог в `game/data/items.json` пишет `python tools/srd_import.py build` из `tools/srd/source` (SRD) и `tools/srd/ru.json`: правка там живёт только до следующей сборки. Редактор говорит это на каждой такой записи и даёт кнопки, куда перенести правку навсегда (нужно открыть корень репозитория):

- **Название и описание → ru.json** — русские тексты записи SRD (у заклинания ещё время, дистанция, длительность) в её ключ `ru.json`.
- **→ promoted.json** — вещь целиком в `tools/srd/promoted.json`: сборка кладёт её в каталог поверх SRD (так же, как `tools/promote_items.py`). Магические вещи и свитки SRD сборка пишет позже — их правьте в источнике.
- **→ tools/srd/backgrounds.json** — предыстория целиком в её источник.

Механика SRD — в `tools/srd/source` или в `tools/srd_import.py`; числа движка — в `rules.json`. После правки источников: `python tools/srd_import.py build`.

## Проверка пакета

`world.html` проверяет пакет на лету (кнопка «Проверка»): схема `game/data/worlds/pack.schema.json` и ссылки по правилам `tools/validate_data.py` (комнаты, выходы, NPC, монстры, вещи, условия заданий, готовые персонажи). Записи с ошибками помечены в списке. Окончательная проверка — после сохранения:

```bash
uv run --project llm_server python tools/validate_data.py
```

Проверки страницы повторяют `validate_data.py` — при новом правиле там добавьте его и в `validatePack` в `world.html`. Игра (`WorldPack.validate`) ещё прогоняет готовых персонажей через создание — это проверяет gdUnit.

## Устройство

`editor-core.js` — общее: JSON с сохранением разметки (разбор с позициями, при записи неизменённые значения копируются из исходного текста), доступ к файлам (папка через File System Access API, `serve.py`, файлы только для чтения), форма, фильтры, связи, подмножество JSON Schema. `assets.html` и `world.html` — только описание коллекций: файл, путь, подписи, ссылки, фильтры. Новый вид данных — ещё одна коллекция в `load()`. `editors.css` — оформление (светлая и тёмная тема).
