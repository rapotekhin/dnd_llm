# Playtest

Живой прогон игры: настоящий `Game` и экраны на dummy-дисплее, ввод как у игрока, реальная модель OpenRouter, скриншот после каждого шага. Ловит то, чего не видят юнит-тесты: падения отрисовки, рассинхрон экранов и потоков, ошибки правил на листе, поведение ЛЛМ.

## Когда срабатывать

- Пользователь просит протестировать / запустить / проверить игру «вживую»
- Перед PR с изменениями в `legacy/game/**` (экраны, gameplay, промпты, билдеры, сейвы)
- Перед PR с изменениями в `game/**` (Godot-клиент) — раздел «Godot-клиент» ниже
- После серии багфиксов — подтвердить, что они работают в игре, а не только в тестах

**НЕ срабатывает на:**
- Правки только `docs/`, ADR, release notes
- Просьбу «прогони тесты» — это `python -m pytest`

## Алгоритм работы

1. **Тесты сначала:** `python -m pytest` должен быть зелёным. Без этого плейтест не начинать.
2. **Ключ:** проверь, что в `.env` есть `OPENROUTER_API_KEY` (`grep -c "^OPENROUTER_API_KEY=." .env`). Значение не печатай никогда. Нет ключа — скажи пользователю и остановись.
3. **Смоук-сценарий:**
   ```bash
   python legacy/scripts/playtest/smoke.py
   ```
   Около 1–2 минут, ~20 вызовов модели (центы). Код выхода: 0 — пройден, 1 — падение, 2 — таймаут шага.
4. **Прочитай** `legacy/scripts/playtest/out/report.txt` (шаги `OK` / `FAIL`, дамп чатов) и **посмотри скриншоты** `out/NN_*.png` инструментом Read: каждый, где менялся экран.
5. **Разбери находки** по категориям: падения и тайм-ауты, баги состояния (экраны, потоки, сейвы), правила 5e (AC, HP, урон, броски), поведение ЛЛМ (разрешает сам то, что должен движок; теряет контекст; род; утечки скрытого), UX (вёрстка, глифы, лишние вызовы).
6. **Падения чини сразу** + регрессионный тест в `legacy/tests/`. Остальное — в таблицу находок [review-2026-10.md](../../../docs/production/review-2026-10.md) §1 (следующий номер B..) и в [roadmap.md](../../../docs/production/roadmap.md).
7. **Повтори смоук** после фиксов и сравни: что ушло, что осталось.
8. **Отчёт пользователю:** что проверено, что подтвердилось (со ссылкой на скриншот), что найдено, что исправлено.

## Как устроен драйвер

`legacy/scripts/playtest/driver.py`:

| Вызов | Что делает |
|---|---|
| `Driver()` | создаёт настоящий `Game` (dummy-дисплей, `pygame.scrap` заглушён), чистит `out/` |
| `frame()` / `pump(sec)` | один кадр главного цикла / кадры N секунд |
| `type_text(s)`, `key(k)`, `click(pos)`, `resize(w, h)` | ввод через очередь событий pygame |
| `wait_turn(what)` | ждёт конца хода: главный экран или диалог ждут ввода, либо открыта торговля |
| `shot(name)` | скриншот в `out/NN_name.png` |
| `make_character(cls, name, gender)` | персонаж как из мастера создания |
| `run_scenario(fn)` | запуск, `report.txt`, код выхода |

**Новый сценарий** — файл рядом (`legacy/scripts/playtest/<name>.py`) с функцией `scenario(d: Driver)` и `sys.exit(run_scenario(scenario))`. Координаты кликов бери из объектов экранов (`d.main().nav_buttons[0].rect.center`), а не из пикселей.

## Подводные камни

- **ЛЛМ недетерминирован.** Один и тот же ввод может открыть диалог, торговлю или просто наррацию. После каждого хода жди `wait_turn` и ветвись по `g.current_screen_name`, а не предполагай экран.
- **Стартовое снаряжение случайно** (у воина — кольчуга или кожаный доспех, со щитом или без), поэтому проверяй AC через правила, а не одним числом.
- Скриншот после `Esc` или клика делай после `frame()` — иначе снимешь старый кадр.
- Dummy-драйвер без буфера обмена — `pygame.scrap` в драйвере уже заглушён.

## Что НЕ делать

- ❌ Не печатать и не логировать ключи из `.env`
- ❌ Не считать «тесты зелёные» доказательством, что игра работает: B22 (падение торговли) жил при зелёных тестах
- ❌ Не утверждать, что фикс работает, не посмотрев скриншот или отчёт шага
- ❌ Не коммитить `legacy/scripts/playtest/out/` (в `.gitignore`)
- ❌ Не гонять плейтест в цикле без нужды — каждый прогон тратит деньги ключа

## Godot-клиент (`game/`)

Тот же подход: настоящая игра с рендерингом, настоящий `llm_server` (пока с заглушкой хода, без денег), сценарий ведёт игру как игрок и снимает скриншот на шаг.

1. gdUnit4 зелёный (команда — в [godot-client.md](../../../docs/tech/godot-client.md#тесты-и-живая-проверка)).
2. `python tools/godot_playtest.py` — сценарий `smoke`: меню → новая игра → действие с `engine.check` → вариант → пауза → сохранение в слот → меню → «Продолжить». Около 15 секунд, на экране мелькнёт окно игры.
3. `python tools/godot_playtest.py --scenario offline` — без сервера: экран «Мастер недоступен» и диагноз.
3a. **После правок промптов, агента, эффектов или режимов** — `python tools/godot_playtest.py --scenario live --real`: настоящая модель (Claude Haiku 5.5 по умолчанию, центы, ключ из `.env`). Вход в таверну, действие, разговор с Бориком через боковую панель, заказ эля, конец разговора, переход на кухню. Жёсткие проверки — на стороне движка (режимы, комнаты, нет упавших ходов), а весь чат лежит в `report.txt`. Прочитай его: мастер не переспрашивает, не описывает оплату и находки без эффектов (строка «ЭФФЕКТЫ»), соблюдает род, держит длину.
4. Прочитай `build/playtest/<сценарий>/report.txt` (строки `OK` / `FAIL`, `RESULT`) и посмотри скриншоты `NN_*.png`; ошибки Godot скрипт печатает отдельно (`godot.log` рядом).

| Вызов в сценарии | Что делает |
|---|---|
| `node("GameState")` | autoload по имени |
| `screen()`, `screen_is("GameScreen")` | текущий экран и проверка его класса |
| `find(screen(), "NewGameButton")`, `find_button_by_text(n, "Сохранить")`, `find_all(n, "CheckCard")` | поиск контролов |
| `press(button)`, `key(KEY_ESCAPE)` | ввод |
| `wait_until(func() -> bool: ..., 30.0)` | ждать условия (ход мастера) |
| `step("что", ok, "детали")`, `shot("имя")` | проверка в отчёт и скриншот |

**Новый сценарий** — `game/tools/playtest/<имя>.gd` с `extends "res://tools/playtest/playtest_base.gd"` и `func run() -> void`, запуск `python tools/godot_playtest.py --scenario <имя>`. Ключевым контролам экранов давай `name`, чтобы сценарий находил их без пикселей.

**Подводные камни Godot:**
- Классы UI в сценарии по имени не упоминать: они ссылаются на autoload-ы, которых ещё нет при компиляции `--script`. Только `screen_is()` / `find_all()`.
- Сценарии требуют `--profile=agent` и чистят его сейвы — сейвы автора не трогаются. Скрипт сам передаёт профиль.
- Esc и горячие клавиши, которые должны работать при фокусе в поле ввода, обрабатывай в `_input`, не в `_unhandled_input` (так нашёлся баг с паузой).
- Порт 8765 занят — останови свой `llm_server`, скрипт сам поднимает сервер с одноразовым токеном.
