# Playtest

Живой прогон Godot-клиента: настоящая игра с рендерингом, настоящий `llm_server` (заглушка хода или реальная модель), сценарий ведёт игру как игрок и снимает скриншот на шаг. Ловит то, чего не видят юнит-тесты: падения отрисовки, рассинхрон экранов и состояния, ошибки правил на листе, поведение ЛЛМ.

## Когда срабатывать

- Пользователь просит протестировать / запустить / проверить игру «вживую»
- Перед тем как назвать готовой правку в `game/**` (экраны, правила, сейвы) или в промптах и агентах бэкенда
- После серии багфиксов — подтвердить, что они работают в игре, а не только в тестах

**НЕ срабатывает на:**
- Правки только `docs/`, ADR, release notes
- Просьбу «прогони тесты» — это gdUnit4 и `uv run pytest` в `llm_server/`

## Алгоритм работы

1. **Тесты сначала:** gdUnit4 зелёный (команда — в [godot-client.md](../../../docs/tech/godot-client.md#тесты-и-живая-проверка)), бэкенд — `cd llm_server && uv run pytest`.
2. `python tools/godot_playtest.py` — сценарий `smoke` на заглушке хода (без денег): меню → новая игра → действие с проверкой → лист персонажа → торговля → карта, журнал, отдых → задание и новый уровень → сохранение → «Продолжить».
3. `python tools/godot_playtest.py --scenario offline` — без сервера: экран «Мастер недоступен» (когда менялась связь).
4. Другие сценарии: `creation --no-server` (создание по шагам), `level_up` (уровни волшебника кликами).
5. **После правок промптов, агента, эффектов или режимов** — `python tools/godot_playtest.py --scenario live --real`: настоящая модель (по умолчанию из ADR-0011, центы). Ключ: проверь `grep -c "^OPENROUTER_API_KEY=." .env`, значение не печатай никогда. Жёсткие проверки — на стороне движка (режимы, комнаты, сделки, нет упавших ходов), весь чат лежит в `report.txt`: мастер не переспрашивает, не описывает оплату и находки без эффектов (строка «ЭФФЕКТЫ»), соблюдает род, держит длину, не упоминает интерфейс.
6. **Прочитай** `build/playtest/<сценарий>/report.txt` (строки `OK` / `FAIL`, `RESULT`) и **посмотри скриншоты** `NN_*.png` инструментом Read; ошибки Godot — в `godot.log` рядом.
7. **Разбери находки:** падения, баги состояния (экраны, сейвы), правила 5e, поведение ЛЛМ, UX (вёрстка, глифы, лишние вызовы). Падения чини сразу + регрессионный тест в `game/test/`; остальное — в [backlog.md](../../../docs/production/backlog.md).
8. **Повтори** после фиксов и сравни; **отчёт пользователю** — что проверено, что подтвердилось (со ссылкой на скриншот), что найдено, что исправлено.

## Как устроен сценарий

| Вызов в сценарии | Что делает |
|---|---|
| `node("GameState")` | autoload по имени |
| `screen()`, `screen_is("GameScreen")` | текущий экран и проверка его класса |
| `find(screen(), "NewGameButton")`, `find_button_by_text(n, "Сохранить")`, `find_all(n, "CheckCard")` | поиск контролов |
| `press(button)`, `tap("имя")`, `key(KEY_ESCAPE)` | ввод |
| `wait_until(func() -> bool: ..., 30.0)` | ждать условия (ход мастера) |
| `step("что", ok, "детали")`, `shot("имя")` | проверка в отчёт и скриншот |

**Новый сценарий** — `game/tools/playtest/<имя>.gd` с `extends "res://tools/playtest/playtest_base.gd"` и `func run() -> void`, запуск `python tools/godot_playtest.py --scenario <имя>`. Ключевым контролам экранов давай `name`, чтобы сценарий находил их без пикселей.

## Подводные камни

- **ЛЛМ недетерминирован.** После каждого хода жди конца (`not gs.is_busy()`) и проверяй режим и комнату, а не предполагай их.
- Классы UI в сценарии по имени не упоминать: они ссылаются на autoload-ы, которых ещё нет при компиляции `--script`. Только `screen_is()` / `find_all()`; ядро (`LevelUp`, `GameSession`) — можно.
- Сценарии требуют `--profile=agent` и чистят его сейвы — сейвы автора не трогаются. Скрипт сам передаёт профиль.
- Esc и горячие клавиши, которые должны работать при фокусе в поле ввода, — в `_input`, не в `_unhandled_input`.
- Порт 8765 занят — останови свой `llm_server`, скрипт сам поднимает сервер с одноразовым токеном.

## Что НЕ делать

- ❌ Не печатать и не логировать ключи из `.env`
- ❌ Не считать «тесты зелёные» доказательством, что игра работает: падение торговли B22 жило при зелёных тестах
- ❌ Не утверждать, что фикс работает, не посмотрев скриншот или отчёт шага
- ❌ Не коммитить `build/` (в `.gitignore`)
- ❌ Не гонять `--real` в цикле без нужды — каждый прогон тратит деньги ключа
