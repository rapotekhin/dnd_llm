# Trace Analyzer

Разбор живой игры автора по полному трейсу сессии (v0.7.1): что происходило, где игра сломалась, где мастер соврал или движок промолчал, где игрок застрял. Итог — список находок с доказательствами из трейса и местом исправления.

## Когда срабатывать

- Автор поиграл и просит посмотреть: «посмотри трейс», «разбери мою игру», «я дошёл до …, глянь что там»
- Автор описывает баг из своей игры («мастер взял деньги, а они не списались») — найти момент в трейсе и подтвердить
- Перед второй попыткой плейтеста — сверить, что прошлые находки не повторились

**НЕ срабатывает на:**
- Скриптовые плейтесты агента (`python tools/godot_playtest.py`, профиль `agent`) — это скилл `playtest`
- Проверку промптов без игры — golden scenarios

## Где трейсы

| Сторона | Путь | Что внутри |
|---|---|---|
| Клиент | `%APPDATA%/Godot/app_userdata/Between the Rolls/traces/<created_at>_<seed>.jsonl` (игры автора); `profiles/agent/traces/` — плейтесты агента | строки `{ts, day, clock, room, mode, ev, …}`; `ev`: `session`, `click` (text, node, screen, pressed), `input`, `nav`, `chat` (entry: kind dm / npc / player / effect / check / system), `combat`, `state` (сжатое состояние на каждое изменение), `turn`, `rpc` (весь JSON-RPC: `turn.request` со снимком, `engine.check` / `engine.validate` / `engine.lookup` и ответы, итог хода), `toast` |
| Бэкенд | `llm_server/var/traces/<date>.jsonl` | на ход: `turn_id`, `kind`, `mode`, `system`, `user`, `messages` (вызовы инструментов модели с ответами движка), `output`, `accepted`, `usage`, `seconds`; ошибки; саммари. Пишется, только если сервер автора запущен с кодом ≥ 0.7.1 |

Один файл клиента — одна игра; загрузка сейва дописывает тот же файл (`session` с `what: load`).

## Алгоритм

1. **Отчёт.** `source venv/Scripts/activate && python tools/trace_report.py` — берёт новейшую игру автора (не агента); `--list` показывает все, путь — конкретную. Отчёт: `build/traces/<имя>.md`.
2. **Сводка и «Что настораживает»** — прочитай первыми. Автоматически ловятся: отклонённые эффекты, упавшие ходы, деньги или передача вещи в тексте без эффекта (оплата кнопкой с ценой не считается), ходы дольше 25 с, подсказки-тосты, одна кнопка 3+ раз подряд, паузы больше 3 минут. Каждый пункт — проверить по контексту, не переносить вслепую: регулярки дают ложные срабатывания.
3. **Маршрут** (mermaid) — куда ходил, где топтался, куда не дошёл.
4. **Ход игры по шагам** — читай целиком, глазами игрока. Ищи то, что автомат не видит (чеклист ниже).
5. **Ходы мастера** — для подозрительных ходов: проверки, эффекты, варианты с ценами, вызовы модели. Если нужно больше — сырой JSONL:
   ```bash
   python -c "import json,sys; [print(l[:400]) for l in open(sys.argv[1],encoding='utf-8') if '\"t-12\"' in l]" "<трейс>"
   ```
   В бэкенд-трейсе по `turn_id` смотри `system` / `user` (что модель знала), `messages` (что она вызывала и что ей ответил движок), `output`.
6. **Состояние** — сверяй `state` до и после спорного места: монеты, вещи, HP, опыт, квесты, время. Слова мастера без изменения состояния (или наоборот) — главный класс багов (ADR-0008).
7. **Итог автору** — по шаблону ниже. Находки, которые чинить, — в `docs/production/roadmap.md` (текущая версия плейтест-фиксов) или `docs/production/backlog.md`; если автор ведёт страницу плейтеста — спроси, добавить ли туда.

## Чеклист: что искать глазами

- **Мастер и движок расходятся:** обещал / отдал / взял / ранил / вылечил / прошло время — а `state` не изменился; изменился без слов; эффект отклонён, а мастер всё равно рассказал как свершившееся
- **Проверки:** действие с риском прошло без броска; бросок не того навыка; DC не по `rules.json`; повтор проверки после провала
- **Мастер знает лишнее:** раскрыл скрытое (секрет, ловушку, мысли NPC) без проверки; NPC говорит о том, чего не видел; в репликах NPC повествование от второго лица («Ты подходишь…»)
- **Лор и тон:** противоречия паку мира, имена не из пака, неверный род героя («парень» для героини), канцелярит, повторы описаний
- **5e:** неверные слоты, урон, КД, состояния, действия в бою, отдых
- **UX:** одна кнопка много раз подряд (не сработала или непонятна), долгие паузы (игрок не знал, что делать), открыл-закрыл окно без действия, ввод текстом того, для чего есть кнопка, тосты-ошибки
- **Цена и скорость:** токены на ход (больше ~20k — повод посмотреть промпт), долгие ходы, стоимость сессии
- **Сам трейс:** пропуски событий, неверный экран в `click.screen`, ходы без пары в бэкенде — это баги инструмента, чини их тоже

## Шаблон итога

```markdown
**Сессия:** герой, мир, время игры, комнаты, ходов мастера, цена.
**Как шло:** 2–4 предложения — путь и впечатление.

**Находки** (сначала серьёзные):
1. **<коротко>** — `14:26:16`, ход `t-5`, комната. Что было (цитата ≤ 1 строки / значения state), почему это баг, где чинить: движок / промпт / UI / пак.
2. …

**Что работает хорошо:** 1–3 пункта (чтобы не сломать при фиксах).
```

## Что НЕ делать

- ❌ Не выдавать автоматические «подозрения» отчёта за баги без проверки по контексту
- ❌ Не цитировать большие куски текста мастера — ссылка на время и `turn_id`
- ❌ Не печатать содержимое `.env` и заголовки авторизации (в трейсах их нет — не добавлять)
- ❌ Не удалять и не править трейсы автора — это его данные; отчёты только в `build/traces/`
- ❌ Не чинить по ходу разбора без согласия — сначала находки автору, потом фиксы (с вопросами перед версией)
- ❌ Не разбирать трейсы профиля `agent` как игру автора
